细化：导入边界状态 + 高级模式

三个状态卡片：导入前、导入失败、以及“原始 JSON”要不要留一个高级入口。

① 导入工作流
拖拽 JSON 文件 / 选择文件 / 粘贴
② 用户需要提供什么
先导入工作流，这里才会开放
＋ 添加输入（不可用）
③ 用户会得到什么
同上，导入后开放

A · 未导入时的空态

步骤 2/3 置灰不可点，只保留一个说明：“先导入工作流”。避免用户填了字段却绑不上节点。

① 导入工作流
✗ 校验失败
第 3 个节点缺少类型信息，无法识别。
常见原因：
· 文件不是 JSON，或不是从 ComfyUI 导出的
· 用的是旧版导出（缺少 API 格式字段）
· JSON 被手动改坏（多了逗号/括号不匹配）
重新选择文件 粘贴别的 JSON 导入不成功不影响已保存内容

B · 校验失败

错误用一句人话 + 常见原因清单，不把 JSON 解析报错甩给用户；失败不破坏当前已保存内容。

② 用户需要提供什么 高级
点击“高级”后展开的只读原始数据：
{ "bindings": { "workflow": {…}, "inputs": [{"key":"reference","node_id":"4","field_path":"image"}] }, "input_schema": {…} }
只读，禁止手改；“高级编辑”需二次确认后才会变成可编辑。

C · 高级模式

默认隐藏，只在页面右上角一个小入口；展开后原始数据只读，真要改需二次确认。普通用户一辈子看不到。

最后一个方向问题：原始 JSON 要不要保留“高级入口”？

1

保留高级模式（推荐）

默认只读，二次确认后才可编辑。留一个逃生口，不影响普通用户体验。

2

彻底去掉 JSON

表单是唯一入口，最干净；代价是万一表单覆盖不到的节点类型，就配不了。
