## Why

配置链路（消息平台 → 工作流 → 任务队列 → 计算节点）已经能在详情页用文字列出健康与上下游，但缺少一张能一眼看清「谁连着谁」的图。链路健康一期明确把 React Flow 全图留到二期；现在详情页和工作台都需要同一套只读配置拓扑。

## What Changes

- 后台用 `@xyflow/react` 画只读配置拓扑：四层节点为消息平台、工作流、任务队列、计算节点；最左一层一个平台一个点（不把菜单入口画成节点）。
- 工作台左栏新增一张卡片，卡片内直接铺可平移缩放的全量画布。
- 工作流、消息平台、任务队列、计算节点四个详情页各有一个按钮，打开弹窗查看「过当前资源的路径」。
- 点图上节点：只高亮经过它的路径，不跳走；再给「打开详情」，点了才进对应详情。
- 节点带绿/黄健康点，与现有链路健康同一套结论；健康数据未就绪不标绿。
- 全图不画没有任何连线的孤立资源。
- 不在图上改绑定、不画运行时任务流水、不替换详情页已有健康检查与引用列表。

不拆成多个 change：画布、图数据、四个入口和工作台卡片共用同一组件与同一套图语义，拆开无法单独验收。

## Capabilities

### New Capabilities

- `config-topology-overview`：配置拓扑图的数据规则、只读画布、路径高亮与「打开详情」、工作台卡片与详情弹窗。

### Modified Capabilities

- `admin-resource-pages`：工作台 MUST 展示拓扑卡片；工作流 / 消息平台 / 任务队列 / 计算节点详情 MUST 提供打开拓扑弹窗的入口。

## Impact

- 前端：`web/admin`（工作台、四类详情页、共用图组件、链路健康结果复用、i18n、合同测试）。依赖已有 `@xyflow/react`。
- 后端：默认不新增接口；图由现有列表 / 挂载 / 路由 / 订阅 / 在线 / 可达性数据在前端组装。
- 文档：不改运行时拓扑与表结构；纯后台展示。
