## Purpose
将后台首页从信息罗列式仪表盘升级为工作台视图，通过欢迎卡与数据大盘（贡献图、概览卡、区间图表），让运维在同屏了解集群健康、负载热点与任务趋势；右侧当前保留占位卡，后续再补充关注信息内容。

## ADDED Requirements

### Requirement: 工作台欢迎卡
系统 MUST 在工作台顶部展示一条全宽欢迎卡（基于 `@kokonutui/mouse-effect-card`），展示当前登录用户的昵称或用户名，并提供新建工作流、添加/管理节点两个快捷入口。欢迎卡内容 MUST 左对齐且垂直居中。欢迎卡 MUST NOT 复现独立的 `dashboard.title` / `dashboard.fullAccuracyNote` 标题说明区块。

#### Scenario: 展示当前用户昵称（左对齐、垂直居中）
- **WHEN** 运维登录后打开工作台首页
- **THEN** 欢迎卡左对齐、垂直居中地展示 `/setup/me` 返回的 `nickname || username`

#### Scenario: 快捷入口可跳转
- **WHEN** 运维点击欢迎卡上的「新建工作流」或「添加/管理节点」
- **THEN** 跳转到对应的工作流新建页或节点管理页

### Requirement: 工作台主体布局
系统 MUST 以数据大盘为主组织工作台主体：贡献图、节点概览卡与区间图表纵向排布；右侧保留一个占位卡（暂不接入真实关注信息）。各统计区块 MUST 可独立加载与失败隔离，任一依赖 API 失败时仅该区块进入错误/空态，其它区块仍可展示。

#### Scenario: 打开工作台看到主区与占位卡
- **WHEN** 运维打开工作台首页
- **THEN** 页面呈现数据大盘与占位卡（占位内容为「待补充」提示）

#### Scenario: 单个区块失败隔离
- **WHEN** 工作台某一统计依赖的 API 请求失败
- **THEN** 仅对应区块进入错误/空态，其它区块照常渲染

### Requirement: 每日任务量贡献图（全年）
在数据大盘顶部 MUST 全宽展示 `kibo-ui/contribution-graph`，以日历热力方式呈现**本年度（1 月 1 日至今天）** 每天执行的任务量，不受全局时间范围控件影响；数据 MUST 来自 `/api/v1/stats/tasks/daily`，为全量按天聚合。

#### Scenario: 展示每日任务量
- **WHEN** 运维打开工作台且统计接口可用
- **THEN** 贡献图按天展示任务量，无数据日期以空态填充

#### Scenario: 全年展示不随范围变化
- **WHEN** 运维切换时间范围或打开工作台
- **THEN** 贡献图始终展示本年度 1 月 1 日至今天的任务量，不受范围控件影响

### Requirement: 节点概览卡片
数据大盘 MUST 提供节点情况卡片（总节点数、生效中节点数）、平均负载卡片、负载最高节点 Top5 卡片。负载数据 MUST 来自 `/stats/fleet`，节点总数与生效数 MUST 来自 `/edges`。三张概览卡 MUST 展示当前实时情况，不受全局时间范围控件影响。

#### Scenario: 展示节点总与生效中
- **WHEN** 运维打开工作台
- **THEN** 节点卡片展示节点总数与生效中节点数

#### Scenario: 展示平均负载
- **WHEN** 运维打开工作台且 fleet 数据可用
- **THEN** 平均负载卡片展示平均 CPU / 内存 / GPU 利用率

#### Scenario: 展示负载最高节点 Top5（实时）
- **WHEN** 运维打开工作台
- **THEN** 负载 Top5 卡片按当前负载从高到低列出最多 5 个节点，不随时间范围变化

### Requirement: 工作流与任务效能区块
数据大盘 MUST 提供「工作流使用热度 Top」与「任务耗时」左右两列，且提供「任务状态分布」与「错误 Top5」左右两列。工作流热度 MUST 来自 `/stats/cases/top`，任务耗时 MUST 来自 `/stats/tasks/daily`，错误码 MUST 来自 `/stats/tasks/errors`（Top5）。卡片 MUST 采用 summary 样式：标题 + 关键指标数字 + 图表；任务耗时图表 MUST 使用渐变面积图呈现。

#### Scenario: 展示工作流使用热度 Top
- **WHEN** 运维打开工作台
- **THEN** 按热度从高到低展示最多 10 个工作流及其任务量与平均耗时

#### Scenario: 展示任务耗时（渐变面积图）
- **WHEN** 运维打开工作台
- **THEN** 以带渐变填充的面积图展示所选范围内的任务耗时（排队 / 执行 / 平均耗时），卡片顶部展示平均耗时指标

#### Scenario: 展示任务状态分布
- **WHEN** 运维打开工作台
- **THEN** 展示成功 / 失败 / 取消的状态分布

#### Scenario: 展示错误 Top5
- **WHEN** 运维打开工作台
- **THEN** 按错误码数量从高到低列出最多 5 个错误码

### Requirement: 右侧占位卡
系统 MUST 在工作台右栏展示一个占位卡，展示「待补充」提示文案，数据关联后续再补充。占位卡 MUST NOT 接入真实关注信息数据。

#### Scenario: 展示占位提示
- **WHEN** 运维打开工作台且存在离线或 Comfy 未运行的节点
- **THEN** 右栏展示「右侧内容待补充」占位提示，不列具体节点

### Requirement: 时间范围联动
工作台 MUST 在数据大盘底部提供时间范围选择（近 7 / 30 / 90 天快捷项与自定义起止日期），该控件 MUST 仅驱动区间型图表（工作流热度、任务耗时、任务状态分布、错误 Top5）；贡献图与节点概览卡 MUST NOT 受其影响。

#### Scenario: 切换时间范围仅影响区间图表
- **WHEN** 运维切换时间范围
- **THEN** 工作流热度、任务耗时、任务状态分布、错误 Top5 按同一范围重新查询；贡献图与节点概览卡保持不变

### Requirement: 仅通过 admin-api 通信
工作台所有数据请求 MUST 仅通过配置的 admin-api 基址访问（`/api/v1/stats/*`、`/api/v1/edges*`、`/api/v1/cases`、`/api/v1/setup/me`），MUST NOT 直连数据库，MUST NOT 依赖前端 mock 层作为交付验收路径。

#### Scenario: 请求指向 admin-api
- **WHEN** 运维加载工作台
- **THEN** 浏览器请求前缀为配置的 admin-api 基址
