## Why

「快速配置」本应让空白平台也能配出一条能跑的工作流，却做成了「选已有工作流 + 隐式默认队列 + 投放门禁」的运营向导。落地页空表、不让人选队列、发布卡 Telegram 菜单，和「工作流只认队列、节点只认队列」也对不上。需要收成「快速新建」：空白时能建工作流、选默认或新建队列、保证队上有人拉活，启用后只带路去配消息平台。

## What Changes

- 侧栏与页名由「快速配置」改为「快速新建」；去掉落地页「选已有工作流」表。有未完成草稿时仍可继续上次。
- 向导改为：① 新建工作流（导入 JSON、输入/输出；向导内**不展示**处理流程表）→ ② 用户**显式**选一条队列（默认或新建或已有自定义队，未选不能继续）→ ③ 节点 → 启用 → ④「还差一步」。工作流编辑页仍保留处理流程表，本次不改那一页、也不给「工作流页新建」偷偷写默认队。
- 投放不再作为发布门禁，也不再作为向导里必配的一步。
- 工作流不绑定节点。提交时只保证所选节点订上所选队列（队上已有人且用户跳过则不改订阅）。不摘掉其他节点的订阅。
- **BREAKING**：旧「快速配置」会话草稿不再兼容，打开即清空。不再支持从本向导改已有工作流。

## Capabilities

### New Capabilities

- （无）行为收口在既有 `quick-config-wizard` 上，不另起能力名。

### Modified Capabilities

- `quick-config-wizard`：入口改名为快速新建；去掉选已有与投放门禁；步骤改为工作流 → 队列 → 节点 → 启用后「还差一步」。
- `admin-web-shell`：侧栏「快速配置」文案与导航语义改为「快速新建」。

## Impact

- 前端 `web/admin`：`features/quick-config` 落地页/flow/步骤/完成页、侧栏 `config/menu.ts`、路由可保留 `/quick-config` 或改为 `/quick-create`（实现时定一处并重定向）、zh/en i18n。
- 复用：`WorkflowEditor`、`CreateEdgeWizard`（含部署）、Topic 列表/创建、`patchEdge(subscribe_topics)`、消息平台页。
- 后端：不改调度；不新增 Case 归属节点字段。空白时依赖已有 `EnsureDefaultTopic`。新建队列走既有 Topic API。
- 文档：管理配置指引中的「快速配置」改为「快速新建」。
