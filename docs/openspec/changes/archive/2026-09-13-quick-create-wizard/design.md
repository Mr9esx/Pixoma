## Context

现状见 `web/admin/src/features/quick-config`：落地页以已有工作流表为主，Formity 四屏为工作流 → 选节点 → 投放 → 完成页门禁。完成页才 `createCase` / `enableCase`，并把选中节点 `subscribe_topics` 并上 `default`。调度仍是「规则命中 Topic，否则回退 `default`」；工作流无归属节点字段。系统启动 `EnsureDefaultTopic`。新建节点复用 `CreateEdgeWizard`（资料 → 部署命令 → 检查通线，可跳过）。动机见 proposal.md。

## Goals / Non-Goals

**Goals**
- 四屏向导：工作流草稿 → 选/建队列 → 节点（可跳过或新建含部署）→ 提交启用 →「还差一步」。
- 工作流只持久化到队列；节点只改订阅；不写 Case 归属节点。
- 旧会话 schema 不匹配则清空。

**Non-Goals**
- 不改调度引擎、不独占队列、不在向导里做多规则分流。
- 不拆工作流编辑页的「处理流程」段，不把工作流页新建改成「没配规则就走默认队」。
- 不在向导里写消息平台菜单。
- 不改节点管理页、消息平台页本身（只跳转进去）。

## Decisions

### D1 — 路由保持 `/quick-config`，只改文案
侧栏与页内文案改为「快速新建」。路径不动，避免菜单/书签断裂。
- 备选：改 `/quick-create` 并重定向。否决：收益小。

### D2 — 启用点在进入「还差一步」之前
节点步点下一步（或跳过）时一次性提交：`createCase`（含必要 routing）→ 按需 `patchEdge` 订阅 → `enableCase`。失败留在节点步。第四屏只展示带路，不再有「保存并发布」。
- 备选：第四屏再发布。否决：与「启用之后才叫还差一步」不符。

### D3 — 用户选中的队列一律写成一条无条件规则
快速新建提交前 MUST 已有用户选中的 topic。无论默认还是自建，都写入一条无条件规则指向该 key（选默认也写 `default`，不靠「空规则回退」）。这样打开工作流页的处理流程能看见这条队，不会看起来像「系统偷偷丢进默认」。引擎的空规则回退语义保留给旧数据，本向导不用它。
- 备选：选默认就留空 routing。否决：和工作流页空保存无法区分，正是「所有新建都进默认」的观感来源。

### D4 — 节点步按队列订阅态分支，文案不提扩容
用现有 `listEdges` + `effective_topics`/`subscribe_topics` 判断队上是否有启用订阅者。有 → 下一步不强制选择；无 → 必须选或新建。选中节点仅在提交时若尚未包含该 topic 则追加，绝不删除他人订阅。
- 备选：队上有人则隐藏节点步。否决：空白后补一台机器没有入口；保留一屏，可空着点下一步。

### D5 — 新建节点复用 CreateEdgeWizard
对话框走资料 + 部署。通线不是离开向导的条件；跳过或未通都记 `selectedEdgeId`。「还差一步」用 `listPresence`：选中节点未 `edge_online && comfy_running`，或未选节点且该队列没有任何在线订阅者 → 显示「节点还没通」。
- 备选：未通禁止启用。否决：已定为可先启用。

### D6 — 会话 version=3
`lib/session.ts` 提高 schemaVersion；缺版本或旧版直接 `clear`。草稿含工作流、所选 topic、可选 edgeId、当前步。启用成功后清会话或标已提交，避免「继续上次」回到已启用流程中途。

### D7 — 只在快速新建里藏处理流程表，工作流页不动
向导内 `WorkflowEditor` 传 `hideProcessing`，不渲染 `TaskFlowTable`。工作流页新建/编辑仍是四段（含处理流程）。不把「瘦身新建 + 默认队」当成工作流页的默认行为。
- 备选：工作流页创建也拆掉第 4 段。否决：空规则启用后全部掉进默认队，不适合本来不该走默认的工作流。

### D8 — 还差一步只跳消息平台
按钮进 `/channels`（或渠道详情若只有一个）。短教程按 voice-profile：短句、落到按钮，不写「请去某页」说明腔。不在本页嵌菜单编辑器。

## Risks / Trade-offs

- [非默认队列用一条无条件规则，日后在分流表里会看到这一条] → 这是工作流认队的可见结果，可接受；文档/空状态不解释「为什么没有画布」。
- [默认队列上已有多台时，新建工作流会和别人抢活] → 符合「只认队列」；不在向导里承诺独占。
- [启用成功后回跳改队列] → 若允许回跳到 1–3，需定义是否再 patch 已启用 Case。本期：启用后只留第四屏与离开；回跳第一步视为新草稿则过于猛。采用：启用后禁止回到 1–3 改草稿，只能离开或去消息平台。
- [CreateTopic 与 createCase 部分成功] → 提交函数按 Topic → Case → 订阅 → enable 顺序；失败停在节点步并保留草稿。

## Migration Plan

1. 上线即清旧 localStorage 会话。
2. 前端替换落地页与四步；投放步与完成页门禁删除。
3. 无需数据迁移。回滚：还原前端，旧会话本就已清空。
