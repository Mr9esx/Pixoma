## MODIFIED Requirements

### Requirement: 入口与落地页
系统 MUST 在侧栏提供「快速新建」入口。无本地未完成草稿时 MUST 直接进入向导第一步，MUST NOT 再要求点一次「创建工作流」。存在本地未完成草稿时 MUST 先展示「继续上次」与废弃草稿；MUST NOT 展示已有工作流列表，MUST NOT 提供选择已有工作流进入向导的路径。

#### Scenario: 从侧栏进入无草稿
- **WHEN** 用户点击侧栏「快速新建」且无本地草稿
- **THEN** 直接进入向导第一步，不可见已有工作流列表，也不再出现单独的创建按钮

#### Scenario: 继续上次
- **WHEN** 用户存在本地会话且点击「继续上次」
- **THEN** 恢复到上次所在步骤

### Requirement: 三步由 Formity 步骤机制驱动
向导 MUST 由步骤机制定义四屏：① 工作流、② 队列、③ 节点、④ 还差一步；库 MUST 一次只渲染当前步骤屏幕；向导 MUST 展示步骤进度与步骤名；已完成步骤 MUST 可回跳，未完成步骤 MUST 不可跳入。

#### Scenario: 一次只渲染当前步骤
- **WHEN** 用户位于向导第二步
- **THEN** 页面只渲染第二步内容与步骤进度，不展示其他步骤内容

#### Scenario: 步骤进度与回跳
- **WHEN** 用户完成第二步后返回第一步
- **THEN** 系统展示第一步已收集状态，可修改后继续

#### Scenario: 未完成步骤不可跳入
- **WHEN** 用户未完成第一步时点击步骤指示器的第二步
- **THEN** 系统禁止跳入并保持当前步骤

### Requirement: 工作流配置步骤
第一步 MUST 仅为新建：要求填写名称（必填）并强制导入合法工作流 JSON（未导入不得前进，不得使用空模板创建），导入后输入/输出字段配置自动生成。本步 MUST 只把工作流草稿记入向导状态，MUST NOT 在本步创建 Case。第一步 MUST NOT 出现新建/已有模式选择。嵌入的工作流编辑器 MUST NOT 展示「处理流程」分流表；目标队列改由第二步选择。

#### Scenario: 未导入工作流阻止前进
- **WHEN** 用户未导入合法 JSON 即点击「下一步」
- **THEN** 系统阻止前进并提示先导入工作流

#### Scenario: 新建工作流并进入下一步
- **WHEN** 用户导入合法 JSON、填写名称并点击「下一步」
- **THEN** 草稿写入向导状态，步骤推进到队列步骤，尚未创建 Case

#### Scenario: 第一步不重复询问模式
- **WHEN** 用户从侧栏进入快速新建第一步
- **THEN** 第一步直接展示新建表单（导入 + 名称/说明），不出现新建/已有模式选择

#### Scenario: 第一步不展示处理流程表
- **WHEN** 用户位于快速新建第一步
- **THEN** 页面可见导入与输入/输出，不可见处理流程分流表

### Requirement: 分步保存与恢复
工作流、队列、节点三步 MUST 只收集草稿，不在步骤间强制落库。离开节点步进入「还差一步」时 MUST 按依赖顺序一次提交：创建并启用 Case、按所选队列写入路由、若用户选了节点则把该节点订阅补上所选队列。本地会话 MUST 保存完整草稿；旧版「快速配置」会话 MUST 在打开时清空。

#### Scenario: 刷新恢复当前步骤
- **WHEN** 用户完成第二步后刷新页面
- **THEN** 恢复到第二步或第三步（按已保存状态），无需重新填写工作流

#### Scenario: 中途退出恢复
- **WHEN** 用户完成前两步后退出，稍后从侧栏进入并点「继续上次」
- **THEN** 从第三步继续，无需重复配置工作流与队列

### Requirement: 错误与失败处理
向导 MUST 将 API 失败展示为可读错误且不丢失已填内容；Topic key 与节点标识 MUST 按系统约束校验；离线节点 MUST 以视觉状态区分，并在「还差一步」提醒。

#### Scenario: API 失败保留内容
- **WHEN** 提交启用时后端返回错误
- **THEN** 向导停留在当前步骤、保留已填内容并展示可读错误

#### Scenario: 非法 Topic key 被拒绝
- **WHEN** 用户输入含大写字母或空格的 Topic key
- **THEN** 系统阻止创建并提示 key 格式约束

## ADDED Requirements

### Requirement: 队列步骤
第二步 MUST 列出已有任务队列（系统默认队列置顶）并提供新建队列。用户 MUST 选择恰好一条队列后才能前进。新建队列的 key MUST 符合系统 Topic 约束。本步 MUST NOT 把工作流绑定到节点。

#### Scenario: 空白平台选择默认队列
- **WHEN** 平台仅有系统默认队列且用户选中它并点击下一步
- **THEN** 向导记录该队列为本次工作流的目标队列，进入节点步骤

#### Scenario: 新建队列
- **WHEN** 用户新建合法队列并选中它后点击下一步
- **THEN** 向导记录该新队列为本次工作流的目标队列，进入节点步骤

### Requirement: 节点步骤
第三步 MUST 展示已有节点并可新建节点（含部署命令与状态检查）。队上已有至少一台已订阅的启用节点时，用户 MUST 可以不选节点直接下一步。队上无人订阅时，用户 MUST 选择已有节点或新建节点后才能下一步。页面 MUST NOT 出现「扩容」类文案。新建节点未通线时 MUST 仍允许继续。本步 MUST NOT 解除其他节点对该队列的订阅。工作流 MUST NOT 记录归属节点。

#### Scenario: 队上已有节点时可跳过
- **WHEN** 所选队列至少有一台启用节点已订阅且用户未选节点即点击下一步
- **THEN** 步骤前进，不修改任何节点订阅

#### Scenario: 队上无人时必须有节点
- **WHEN** 所选队列没有任何启用节点订阅且用户未选/未建节点即点击下一步
- **THEN** 系统阻止前进

#### Scenario: 新建节点含部署且可跳过通线
- **WHEN** 用户新建节点并进入部署屏后选择跳过通线检查
- **THEN** 该节点被记为向导选中节点，步骤仍可继续

### Requirement: 启用与还差一步
进入第四屏之前，系统 MUST 创建并启用该工作流：MUST 写入一条无条件规则指向用户所选队列（含系统默认队列）；若用户选了节点且该节点尚未订阅所选队列，MUST 补上订阅。未选择队列 MUST NOT 启用。第四屏标题 MUST 为「还差一步」：提供进入消息平台配置的按钮与短教程；投放 MUST NOT 作为启用门禁。若本次选中节点未通线，或跳过节点但所选队列当前没有任何在线可拉活的节点，第四屏 MUST 额外提醒节点还没通。

#### Scenario: 默认队列启用
- **WHEN** 用户选择默认队列、队上已有节点并跳过选节点后进入第四屏
- **THEN** Case 已创建并启用，routing 含一条指向 `default` 的无条件规则，未改节点订阅

#### Scenario: 选了未订阅节点则补订阅
- **WHEN** 用户选择一条队列并指定一台尚未订阅该队列的节点后进入第四屏
- **THEN** Case 已启用，该节点 subscribe_topics 包含所选队列

#### Scenario: 未通线仍启用并提醒
- **WHEN** 用户新建节点后跳过通线并进入第四屏
- **THEN** Case 已启用，第四屏显示节点还没通的提醒，且可见进入消息平台的按钮

#### Scenario: 投放不挡启用
- **WHEN** 平台没有任何消息平台且用户进入第四屏
- **THEN** 工作流已启用，第四屏仍可进入消息平台页

## REMOVED Requirements

### Requirement: 处理流程步骤
**Reason**: 快速新建不再配置分流画布；工作流只认一条队列。
**Migration**: 多规则分流在任务分流/工作流编辑页配置，不走本向导。

### Requirement: 投放步骤
**Reason**: 投放改为启用后的带路，不再作为向导内配置步。
**Migration**: 第四屏按钮进入消息平台页配置菜单。

### Requirement: 完成页就绪清单与发布门禁
**Reason**: 启用不再等待投放与处理流程清单全绿。
**Migration**: 节点与队列约束改在节点步与启用提交时检查；投放引导改在「还差一步」。
