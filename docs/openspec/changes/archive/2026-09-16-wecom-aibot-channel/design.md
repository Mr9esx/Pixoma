## Context

最初的企业微信渠道范围在实施中收敛。已交付的共享会话迁移、飞书工厂分离和适配器安全重建不依赖企业微信，保留为本 change 的最终成果。

## Goals / Non-Goals

**Goals:**

- 平台无关的会话决策只保留一份实现。
- Telegram 保持现有行为，飞书走独立的运行时工厂路径。
- 凭证更新或停用时不让新旧适配器重叠运行。
- 移除未完成且不再需要的企业微信接入面。

**Non-Goals:**

- 不实现企业微信、个人微信、ClawBot 或 iLink。
- 不增加新的消息平台表单、配置字段或后台页面。

## Decisions

### 1. 会话控制器拥有平台无关决策

`internal/channels/conversation` 负责能力调用、会话状态、一次性动作、返回导航、菜单/卡片决策、结果渲染决策和异步通知。平台适配器负责事件解码、媒体转存和协议渲染。

这样 Telegram、飞书及后续平台复用同一套业务交互，而不会把 SDK 类型泄漏到应用层。

### 2. 平台工厂显式分发

运行时工厂按平台创建 Telegram、飞书或 MCP 路径。飞书不再经过 Telegram Bot 初始化；通知处理器在飞书适配器启动成功后注册，在停止成功后注销。

### 3. 停止成功是替换的前置条件

Assembler 对同一渠道的凭证变更先停止旧适配器。只有停止成功才创建替代实例；停止失败时记录 `error` 状态，并跳过该轮启动。

该规则对全部 IM 平台生效，避免重复连接、重复消费和重复通知。

### 4. 企业微信代码整体撤回

企业微信不再是有效的平台类型。对应凭证、HTTP DTO、健康探测分支、协议客户端、测试和 Go 模块依赖一并删除；不保留无法启动的占位实现。

## Verification

- 共享控制器与 Telegram 测试覆盖文本、媒体、菜单、卡片、导航和通知。
- 飞书工厂测试证明不会创建 Telegram Bot。
- Assembler 测试覆盖停止失败时不创建替代实例。
- 渠道领域测试覆盖 `wecom` 不再是有效平台。
- 运行渠道相关 Go 包测试，并检查模块依赖和 diff 空白错误。
