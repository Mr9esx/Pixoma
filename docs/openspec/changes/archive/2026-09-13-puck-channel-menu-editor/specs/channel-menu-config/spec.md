## MODIFIED Requirements

### Requirement: 菜单按消息平台作用域存储
系统 MUST 将菜单配置归属到消息平台：每个消息平台一份嵌套树文档（根为主键盘，按钮下可挂卡片子树）；菜单读取与整份替换均以消息平台 id 为作用域，不同消息平台互不影响。

#### Scenario: 消息平台各自菜单独立
- **WHEN** 存在两个消息平台并分别保存菜单树
- **THEN** 各消息平台读取到的菜单互不串扰

#### Scenario: 不存在消息平台被拒绝
- **WHEN** 对不存在的消息平台 id 读取或保存菜单
- **THEN** 返回 404 且不创建隐式菜单

### Requirement: Case 挂载与反查
系统 MUST 支持按钮动作引用 Case/工作流（作为打开工作流的参数）并从 Case 反查其出现的菜单路径；引用的 Case 必须存在，否则拒绝保存。路径 MUST 按树从主键盘按钮走到该动作节点的可读标签序列表达。卡片不是独立资源，MUST NOT 再按卡片 id 做跨菜单项共享。

#### Scenario: 保存键盘按钮并挂载 Case
- **WHEN** 管理面在消息平台菜单树的某按钮上设置打开工作流，参数引用已存在的 Case 后保存
- **THEN** 持久化成功，后续读取可见该按钮及其 Case 引用

#### Scenario: 绑定不存在的 Case 被拒绝
- **WHEN** 提交的打开工作流动作引用不存在的工作流/Case id
- **THEN** 系统拒绝保存并返回可理解的校验错误

#### Scenario: 查询 Case 的菜单挂载
- **WHEN** 调用方请求某 Case 的菜单挂载
- **THEN** 系统返回零条或多条路径；每条能标识所在消息平台、节点与从根键盘起的可读路径

### Requirement: 默认种子按消息平台
系统在消息平台无自定义菜单时 MUST 提供可用的默认嵌套树；默认树 MUST 包含至少一条打开工作流入口（挂载图片类 Case，若该 Case 存在）以及一条帮助类发文字入口。

#### Scenario: 空配置使用默认种子
- **WHEN** 消息平台尚无自定义菜单
- **THEN** 运行时仍能得到可用的根键盘按钮集合

## ADDED Requirements

### Requirement: 菜单文档为嵌套树
菜单文档 MUST 以嵌套树表达：根节点描述主键盘（含列数与按钮列表）；每个按钮有文案与动作；动作为打开卡片时 MUST 内嵌一张卡片（正文和/或媒体、以及卡片按钮列表）；卡片按钮结构与键盘按钮相同，可再嵌卡片。同一张卡片 MUST NOT 被多个按钮引用。

#### Scenario: 打开卡片写在子树里
- **WHEN** 保存一个键盘按钮，动作为打开卡片且卡片上有两个按钮
- **THEN** 再次读取时该卡片完整出现在该键盘按钮之下，而不是出现在独立卡片数组并用 id 回指

#### Scenario: 拒绝卡片复用引用
- **WHEN** 提交的文档试图让两个按钮指向同一张外部卡片 id 而不内嵌副本
- **THEN** 系统拒绝保存

## REMOVED Requirements

### Requirement: 菜单模型平台中立
**Reason**: 编辑器与文档改为手机画布上的键盘/卡片嵌套树，列数、媒体、按钮动作属于文档本身；不再维护「capability_id + 平台渲染声明」那套中立核心字段。
**Migration**: 无。旧 Menu/Card 与能力树配置作废，渠道按新树重配或使用默认树。
