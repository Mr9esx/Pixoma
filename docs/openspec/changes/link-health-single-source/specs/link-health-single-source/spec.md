## Purpose

让配置链路上的绿黄只有一个主人：控制面组装器按完整活路给出结论，后台各页只渲染，避免再靠每个页面记得去看上游。

## ADDED Requirements

### Requirement: 唯一健康组装器
系统 MUST 提供管理侧只读查询作为配置链路（消息平台 → 工作流 → 任务队列 → 计算节点）的健康与关联真相源。该查询 MUST 一次返回图上的节点、连线、每个节点的健康、断点与上下游引用。MUST NOT 修改任何配置。鉴权 MUST 与既有管理 API 相同。

#### Scenario: 已登录可读取全图与健康
- **WHEN** 持有有效管理员会话的客户端请求该查询
- **THEN** 返回四类节点、连线，以及每个节点的健康状态

#### Scenario: 未登录被拒
- **WHEN** 无管理员会话的客户端请求该查询
- **THEN** 请求因未认证被拒绝，且不返回图数据

#### Scenario: 查询不改配置
- **WHEN** 客户端连续两次请求且期间无人改配置
- **THEN** 菜单挂载、工作流路由、节点订阅均保持不变

### Requirement: 打开消息平台可异步踢一轮探测
系统 MUST 提供管理侧异步探测踢脚（对已启用通道执行与后台 `ReachabilityProbe` 相同的 ProbeOnce）。该踢脚 MUST 在 Telegram 往返完成前返回。MUST NOT 让列表或健康查询等待这次探测。MUST NOT 恢复打开详情时同步 POST `/channels/{id}/check` 并卡住页面的做法。

#### Scenario: 踢脚立刻返回且探测仍会跑
- **WHEN** 已登录客户端对踢脚接口发起请求，且 Telegram getMe 尚未返回
- **THEN** 该请求在探测完成前即以成功被接受结束；探测仍会对已启用通道写入 last_check

### Requirement: 活路不变式
工作流、任务队列、计算节点的展示健康 MUST 满足：自身无断点，并且至少存在一条完整可用路径（可用的消息平台 → 该资源所在位置 → 就绪计算节点）。某一跳不可用且没有别的活路时，所有必须经过它才能跑通的资源 MUST 为存在问题。另有活路时，该资源自身 MUST 仍为正常，不可用的那一跳 MUST 在引用里标为存在问题。该规则 MUST NOT 写成只针对某一种资源或某一种故障（例如只处理通道进程）。

就绪计算节点 MUST 同时满足：已启用、节点在线、Comfy 运行中。消息平台是否可作为路径起点 MUST 由组装器按该平台全部可见运行信号合成，MUST NOT 在工作流页用一套信号、在平台页用另一套。

#### Scenario: 唯一入口不可用
- **WHEN** 某工作流只挂在一个消息平台上，且该平台按组装器结论不可用，下游队列与节点均就绪
- **THEN** 该工作流健康为存在问题；对应平台引用为存在问题

#### Scenario: 双入口仍有活路
- **WHEN** 某工作流同时挂在平台 A 与平台 B；A 不可用，B 可用，且经 B 可到达就绪节点
- **THEN** 该工作流健康为正常；A 的引用为存在问题；B 的引用为正常

#### Scenario: 唯一节点不可用
- **WHEN** 某工作流经可用平台可达，但其路由队列上没有任何就绪计算节点
- **THEN** 该工作流与该队列健康均为存在问题；对应节点引用为存在问题

#### Scenario: 新 hop 走同一规则
- **WHEN** 将来增加一类必须经过才能跑通的资源，且它是某工作流唯一路径上的不可用 hop
- **THEN** 该工作流仍不得标绿，且验收靠同一条活路不变式，而不是给工作流页再加一个 if

### Requirement: 运行信号对组装器可见
凡进入绿黄判定的运行态（适配器、探测、节点心跳等）MUST 能被组装器读到。只存在于某一个页面请求缓存、组装器读不到的信号 MUST NOT 作为全图健康输入。组装器所需输入缺失时，相关节点 MUST 为未就绪，MUST NOT 显示为正常。

#### Scenario: 只在详情页才有的信号不能让别的页标绿
- **WHEN** 某运行信号仅在打开某一资源详情时才会被取到，组装器尚未读到它
- **THEN** 依赖该信号的节点不得显示为正常

#### Scenario: 列表与详情同色
- **WHEN** 同一工作流在列表显示存在问题
- **THEN** 打开其详情时健康结论同为存在问题

#### Scenario: 查询失败不标绿
- **WHEN** 健康查询失败或仍在加载
- **THEN** 列表圆点、详情与拓扑均不得把该资源显示为正常

#### Scenario: 尚未探测的消息平台不得标绿
- **WHEN** 某消息平台适配器在跑，但 last_check 为空
- **THEN** 该平台健康为未就绪，MUST NOT 为正常

#### Scenario: last_check 为故障时不得写链路正常
- **WHEN** 某消息平台 last_check 为 network、auth 或 other
- **THEN** 该平台健康 MUST NOT 为正常；详情「状态与关联」MUST NOT 显示链路正常

### Requirement: 页面不得发明绿黄
管理后台的工作流、消息平台、任务队列、计算节点列表与详情，以及配置拓扑，MUST 使用组装器返回的健康。MUST NOT 再用页面内拼接多份列表的方式计算绿黄。

#### Scenario: 工作流列表不再本地拼健康
- **WHEN** 运维打开工作流列表
- **THEN** 列表圆点来自健康查询，而不是该页自行请求菜单挂载后再本地判定

#### Scenario: 拓扑与详情同色
- **WHEN** 某工作流详情健康为存在问题
- **THEN** 工作台拓扑与该工作流焦点弹窗上对应节点均为黄色
