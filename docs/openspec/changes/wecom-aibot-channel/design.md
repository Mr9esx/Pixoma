## Context

见 `proposal.md` 的 Why。依赖 `feishu-channel` 已按平台分支的工厂与表单。企微官方智能机器人协议是 WSS + `aibot_subscribe`；无官方 Go SDK，社区库或自写均可，须能停净单连接。模板卡片与媒体上传在长连接上可用，不必公网 CallbackUrl。

## Goals / Non-Goals

**Goals:**

- 本机一条 WSS 跑通私聊/群 @ 出图。
- 热重载不互踢丢消息。

**Non-Goals:**

- 不实现自建应用 HTTP 回调。
- 不引入必须公网的卡片 CallbackUrl。

## Decisions

### 1. 只接智能机器人

- **选择**：`PlatformWeCom` 本期语义 = 智能机器人（Bot ID + Secret + WSS）。自建应用回调列为明确非目标。
- **理由**：后者要公网 URL 与可信 IP，和本机模型冲突。
- **备选**：两种企微都做——范围膨胀且部署前提相反。

### 2. 协议实现允许自写

- **选择**：用最小 WSS 客户端实现订阅/心跳/重连/回复/主动推送；或引入可审计的社区 Go 库。禁止把 Node 官方 SDK 嵌进 Go 主进程。
- **理由**：主语言是 Go；官方 Go SDK 不存在。
- **备选**：另起 Node sidecar——多一个进程，装配与热停更难。

### 3. 菜单 → 欢迎语 + 模板卡片

- **选择**：`enter_chat` 5 秒内发欢迎/入口卡片；按钮事件走同一条 WSS。`SendMedia` 走上传 + 回复或 `aibot_send_msg`。
- **理由**：智能机器人没有 TG 键盘。
- **备选**：纯命令——能跑，但丢掉已有菜单配置。

### 4. 单连接由 Assembler 保证

- **选择**：Create 前 Stop 旧适配器并等到连接退出；探测不得另开第二条业务 WSS（探测用短请求或复用健康状态）。
- **理由**：平台限制同一 bot 一条连接，新连接踢旧连接。
- **备选**：探测也拨 WSS——会把正在服务的连接踢掉。

## Risks / Trade-offs

- [社区库质量] → 协议面写集成测试；库可替换。
- [流式 6 分钟不够出图] → 规格已要求主动推送兜底。
- [私有化企微 WSS 地址不同] → 凭证可可选覆盖 `ws_url`，默认公有云地址。
