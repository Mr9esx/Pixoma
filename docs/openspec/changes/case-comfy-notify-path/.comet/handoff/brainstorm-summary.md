## 确认的技术方案

用户已确认做法 A。

执行时按任务查出 Case，复制工作流 JSON，读已保存的用户输入，写入节点后再提交 Comfy。

### 数据流

1. TG：用户选 Case → 按顺序要文本 / 用户图片（发照片）→ 确认
2. 确认时：校验 → 把输入存到本地对象存储 → 建任务 → 发「任务已创建」
3. 调度：把任务派到本机执行器
4. 执行器：取 Case 里的工作流 JSON → 复制一份 → 读已存输入 → 用户图片先上传到 Comfy → 把文本和上传后的文件名写进节点 → Submit → Wait → 产物存本地 → 上报成功/失败
5. 通知：TG 把产物图发给用户（发送用的文件名只用最后一段，不要带路径）

### 配置

- `comfy_mock: true`：不上真实 Comfy，仍走同一套「复制工作流 + 写入输入」；上传返回假文件名；产物用假图
- `comfy_mock: false`：连 `comfyui_base_url`（可指到 `192.168.31.131:8188`）

### 预置 Case 文件

- 工作流 JSON 放进仓库（从远程拷贝 `klein9b-edit.api.json`）
- Case 配置写明输入项与节点绑定；启动时写入数据库目录

## 关键取舍与风险

- 做法 A 比「确认时就把写好的工作流塞进内存表」更稳：重试/对账仍能从 Case + 已存输入重建
- 远程模型文件名写死在工作流里：服务器缺模型会失败，需在失败信息里能看出来
- TG 对外文案与工作流内容可分开（名称可中性，工作流本身不变）
