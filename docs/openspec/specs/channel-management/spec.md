# channel-management Specification

## Purpose
消息平台是管理台的一级实体：代表接入某个消息平台（Telegram、飞书、企业微信、钉钉等）的配置实例，包含平台类型、凭证与启停状态。消息平台管理负责创建、查看、启停消息平台并驱动对应 Bot 运行时装配，使菜单配置与消息投递获得明确归属。
## Requirements
### Requirement: 消息平台实体与持久化
系统 MUST 将消息平台持久化为独立实体，字段至少包含：消息平台 id（稳定字符串）、平台类型（如 `telegram`）、显示名称、凭证（如 TG Bot Token）、启用状态、创建/更新时间。同一平台 MAY 存在多个消息平台实例（数据模型层面预留）。

#### Scenario: 创建消息平台
- **WHEN** 管理员在管理台创建消息平台并选择平台 Telegram、填写 Bot Token
- **THEN** 系统保存该消息平台并可列出；凭证以安全方式存储，不直接明文回显

#### Scenario: 消息平台列表与详情
- **WHEN** 管理员打开消息平台管理页
- **THEN** 可见全部消息平台的平台、名称、启用状态，并可进入详情查看与编辑

### Requirement: 消息平台 CRUD 管理 API
admin-api MUST 暴露消息平台管理 HTTP 接口，支持创建、列表、详情、更新与删除（或等价启停语义）；鉴权策略与既有 admin-api 一致（仅内网约定）。

#### Scenario: 创建并读取消息平台
- **WHEN** 客户端 POST 创建消息平台（平台 + 凭证 + 名称）后 GET 列表
- **THEN** 返回 200 且列表包含新消息平台

#### Scenario: 非法平台被拒绝
- **WHEN** 客户端提交未知平台类型或空凭证
- **THEN** 返回 4xx 与错误说明，且不创建消息平台

### Requirement: 运行时按消息平台装配
系统 MUST 依据启用的消息平台配置装配 Bot 运行时：消息平台启用且凭证有效时对应平台适配器启动；消息平台禁用或凭证缺失时对应适配器 MUST NOT 启动。Bot Token 仅存于消息平台凭证，MUST NOT 从环境变量或 `platform_settings` 读取。

#### Scenario: 启用消息平台后 Bot 可启动
- **WHEN** 存在启用且凭证完整的 Telegram 消息平台
- **THEN** 运行时启动对应 TG Bot，主菜单可响应

#### Scenario: 禁用消息平台后 Bot 不启动
- **WHEN** 消息平台被禁用
- **THEN** 对应平台适配器不启动（或停止），不再处理该消息平台事件

#### Scenario: 无凭证消息平台不启动
- **WHEN** 消息平台启用但凭证缺失或为空
- **THEN** 对应平台适配器 MUST NOT 启动，并记录可诊断错误

### Requirement: 消息平台变更热生效
消息平台创建、启用/停用或凭证更新后，系统 MUST 在无需重启进程的情况下使对应适配器生效：启用/创建 → 启动适配器；停用 → 停止适配器；凭证更新 → 重建适配器。生效延迟 MUST 在数秒量级。

#### Scenario: 创建消息平台后热启动
- **WHEN** 管理员创建启用且凭证完整的 Telegram 消息平台
- **THEN** 无需重启进程，适配器在数秒内启动并可响应消息

#### Scenario: 停用消息平台热停止
- **WHEN** 管理员停用运行中的消息平台
- **THEN** 对应适配器在数秒内停止，不再处理事件

#### Scenario: 凭证更新后重建
- **WHEN** 管理员更新运行中消息平台的 Bot Token
- **THEN** 适配器以新凭证重建，旧连接停止

### Requirement: 消息平台删除受限
系统 MUST 禁止删除未禁用或仍被引用的消息平台：删除仅在消息平台已禁用且无活跃会话/任务引用时允许（或采用软删除）；违规删除 MUST 返回 4xx 与可理解原因。

#### Scenario: 启用中删除被拒
- **WHEN** 客户端删除启用中的消息平台
- **THEN** 返回 4xx，消息平台保持不变

#### Scenario: 禁用且无引用可删除
- **WHEN** 消息平台已禁用且无活跃会话/任务引用
- **THEN** 删除成功（或软删除后不可见）
