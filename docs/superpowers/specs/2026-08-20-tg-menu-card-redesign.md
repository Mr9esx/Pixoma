# TG 菜单 / 卡片：从 TG 原生概念出发的完全重构

## 1. 背景与结论

经过多轮原型迭代，结论：此前「菜单项 = 树节点 + 能力」的模型把 TG 的**菜单、卡片、消息**混在了一起，还自加了「主键盘 ≤6」「只能一层分组」等 TG 并不存在的限制。本次**完全重构**（不兼容旧数据/旧接口），以 TG 原生概念建模：

- **底部键盘（ReplyKeyboard）**：常驻输入框下方的按钮网格，行/列完全自由，无数量上限；
- **消息（Message）**：一条内容（文字/图片/视频/媒体组），可带按钮；
- **卡片按钮（InlineKeyboard）**：挂在消息上的按钮，每个 = 显示文字 + 动作（回调/链接等）。

用户最终确认的模型：

1. **菜单（主键盘）** = 独立定义：一组菜单项 + 布局（每行按钮数）；
2. **菜单项** = 名字 + 点击动作（弹出卡片 / 直接执行工作流 / 发文字 / 发媒体 / 链接 / 复制 / 暂未开放）；
3. **卡片** = 独立定义：媒体 + 文字 + 按钮列表（卡片由菜单项/按钮「就地」创建，也可从已有卡片复用）；
4. **卡片按钮** = 名字 + 动作，动作词汇与菜单项一致；「打开卡片」可无限往下（消息链天然支持任意深度与循环）。

## 2. 目标与边界

**目标：**

- 数据模型与交互完全对应 TG 的真实交互（主键盘 / 消息 / 卡片按钮）；
- 编辑器所见即所得：左边 TG 手机模拟，右边沿链分层编辑（⓪ 菜单 → ① 菜单项 → ② 卡片 → ③ 按钮 → ④ 卡片……）；
- 卡片就地创建，不要求「先建卡片再配菜单」；卡片可复用、可查找；
- 动作词汇 = TG 原生支持的能力：打开卡片 / 打开工作流 / 发文字 / 发媒体 / 跳转链接 / 复制文本 / 暂未开放；
- 校验只在保存时执行；返回按钮自动生成（回来源 / 回主菜单），不要求手动配置。

**非目标：**

- 不做旧数据迁移与旧接口兼容（完全重构，旧 `MenuNode` / `capability` 菜单模型废弃）；
- 不做飞书 / 企微等其它消息平台适配器（模型按 TG 原生定义，后续消息平台另行抽象）；
- 不做工作流（Case）执行本身——只做「按钮点击 → 调起工作流流程」的入口动作；
- 不做扣费 / 会员 / 签到业务实现；
- 不做权限 / 多管理员协作。

## 3. 数据模型（全新）

```ts
// 菜单（主键盘）
type Menu = {
  id: string
  name: string
  columns: number            // 每行按钮数，1-8，自由
  items: MenuItem[]          // 菜单项，顺序即显示顺序
}

// 菜单项（主键盘上的一个按钮）
type MenuItem = {
  id: string
  label: string
  action: Action
}

// 卡片（用户看到的一条消息）
type Card = {
  id: string
  name: string               // 管理用名字（可复用、可搜索）
  media: Media[]             // 图片/视频，可多张
  text: string
  buttons: CardButton[]      // 卡片按钮，顺序即显示顺序
}

type CardButton = {
  id: string
  label: string
  action: Action
}

// 动作（按钮点击后发生什么）
type Action =
  | { type: 'open_card'; card_id: string }          // 打开卡片（指向另一张卡片）
  | { type: 'open_workflow'; workflow_ids: string[]; mode: 'list' | 'direct'; direct_id?: string } // 打开工作流
  | { type: 'send_text'; text: string }             // 回复一段固定文字
  | { type: 'send_media'; media: Media[]; text?: string } // 发媒体（可带文字）
  | { type: 'open_url'; url: string }               // 跳转链接（TG URL 按钮）
  | { type: 'copy_text'; text: string }             // 复制文本（TG copy_text）
  | { type: 'placeholder' }                          // 暂未开放

type Media = {
  kind: 'image' | 'video' | 'animation'
  url: string
  caption?: string
}
```

说明：

- 卡片图允许任意深度与循环（每次点击都是一条新消息，无运行风险）；
- 卡片是独立对象，可被多个菜单项/按钮引用（复用）；「卡片清单」用于查找、重命名、删除引用；
- `open_workflow.mode`：`list` = 点按钮后列出可选工作流让用户选；`direct` = 直接开始指定工作流（未来能力，本期可实现 `list`，`direct` 预留）。

## 4. 交互设计（编辑器）

### 4.1 整体布局

```
┌─────────────────────────────────────────────────────────────┐
│ 图片助手   面包屑：主键盘 › 图片生成 › 卡片 › 风格说明  保存 │
├───────────────────────────────┬─────────────────────────────┤
│ 用户视角（手机模拟）           │ 分层编辑（一条链往下展开）    │
│ 消息流 + 卡片 + 主键盘          │ ⓪ 菜单（主键盘）定义          │
│ 点按钮往下走、面包屑回跳        │ ① 菜单项                    │
│                                │ ② 卡片（就地）              │
│                                │ ③ 卡片按钮                  │
│                                │ ④ 下一张卡片……             │
└───────────────────────────────┴─────────────────────────────┘
```

### 4.2 分层编辑

- **⓪ 菜单（主键盘）**：菜单项列表（名字 + 动作摘要 + 排序）+ 每行按钮数 + 加/删菜单项；
- **① 菜单项**：名字 + 点击后做什么（动作选择）+ 动作参数（如「弹出卡片」→ 就地新建或从已有卡片选）；
- **② 卡片**：媒体（上传/链接，可多张）+ 文字 + 卡片按钮列表；
- **③ 卡片按钮**：名字 + 动作 + 参数；「打开卡片」→ 就地新建/选择目标卡片并继续展开；
- 面板随「当前编辑对象」滚动展示已展开的层；面包屑可点击回跳任意层。

### 4.3 关键交互规则

- **所见即所得**：左手机模拟 = 主键盘 + 消息流；点菜单项/按钮，模拟发出对应卡片/文字/工作流入口；点「返回」回到上一张。
- **就地创建**：选「打开卡片」时默认「新建一张卡片（就地编辑）」，另有「从已有卡片选」入口；不存在「必须先建卡片」。
- **返回自动生成**：每张卡片自动带「‹ 返回」按钮（返回来源卡片）；从主键盘直接进入的卡片返回 = 返回主菜单；不要求手动配置。
- **校验只在保存时**：编辑中不弹全局红条；保存时聚合提示（按钮没选动作 / 打开卡片没选目标 / 打开工作流没选工作流 / 按钮名空等），并定位到具体对象。
- **卡片清单**：辅助视图（搜索 / 重命名 / 查看被哪些入口引用 / 删除引用），不是配置前置。

### 4.4 动作参数表单

| 动作 | 参数表单 |
|---|---|
| 打开卡片 | 目标卡片选择器（新建 / 搜索已有） |
| 打开工作流 | 工作流多选列表 + 模式（list 本期；direct 预留） |
| 发文字 | 多行文本 |
| 发媒体 | 媒体上传/链接列表 + 可选文字 |
| 跳转链接 | URL 输入（校验 http/https） |
| 复制文本 | 多行文本 |
| 暂未开放 | 无参数 |

## 5. 后端改动

### 5.1 领域模型

- 废弃 `internal/menu/domain` 的 `MenuNode` 树 + `CapabilityID/Params` 菜单模型（不迁移、不兼容）；
- 新增领域对象：`Menu` / `MenuItem` / `Card` / `CardButton` / `Action`（与 §3 一一对应，Go 类型 + JSON 序列化）；
- 卡片为独立聚合（可被引用），删除卡片前校验引用（阻止删除被引用的卡片，或列出引用让用户处理）。

### 5.2 运行时

- 菜单渲染：主键盘 = `Menu.columns` 布局 + `Menu.items` 标签；点击菜单项 → 按 `Action` 分发：
  - `open_card` → 发送目标卡片（媒体 + 文字 + 卡片按钮，含自动「返回」）；
  - `open_workflow` → 调起工作流流程（复用现有 `open_case` 能力入口）；
  - `send_text` / `send_media` / `open_url` / `copy_text` / `placeholder` → 对应 TG 原生能力；
- 卡片按钮点击 → 同上分发；「返回」按钮由运行时动态生成（记录来源链）。
- 能力注册表（`capability.Registry`）继续作为「工作流」等真实能力执行入口；展示类动作由动作模型直接表达，不再注册为菜单「能力」。

### 5.3 存储

- 新表/新文档结构：`menus`（主键盘）、`cards`（卡片聚合：media/text/buttons）、`menu_items`（或内嵌于 menu）；
- 索引：卡片名搜索；菜单消息平台归属（每个消息平台一个菜单）。

### 5.4 管理 API（全新路由，不兼容）

- `GET/PUT /api/v1/channels/{id}/menu` → `Menu`（含 items 内嵌）
- `GET/POST /api/v1/cards`、`GET/PATCH/DELETE /api/v1/cards/{id}`（卡片 CRUD + 搜索）
- `GET /api/v1/cards/{id}/references`（被哪些入口引用）
- `GET /api/v1/channels/{id}/menu/preview` → 运行时渲染预览（或前端本地模拟，二选一：本期前端本地模拟，服务端预览端点保留可选）

## 6. 前端改动

- 删除现有 `channel-menu-editor.tsx` / `phone-simulation.tsx` / `node-config-panel.tsx` / `menu-simulation.ts` / `menu-validate.ts` 的旧实现（被本设计取代）；
- 新编辑器：`MenuEditor`（分层链式编辑）+ `PhoneSimulation`（完整手机模拟）+ `ActionForm`（动作参数表单）+ `CardPicker`（卡片选择/新建）+ `CardListPanel`（卡片清单）；
- 纯函数：`buildTgFlow(menu, cards)`（模拟主键盘与卡片流）、`validateMenuConfig(menu, cards)`（保存时校验）；
- i18n 全量更新为最终文案（菜单项/卡片/动作/返回/就地新建等）。

## 7. 测试策略

- 后端：领域模型序列化往返；动作分发（open_card/open_workflow/send_text/…）；卡片引用校验；菜单布局（columns 自由、无上限）；返回链生成；
- 前端：`buildTgFlow` / `validateMenuConfig` 单测；动作参数表单 contract 测试；分层编辑器 contract 测试；卡片选择/复用测试；
- 端到端：mock TG 下「主键盘 → 菜单项 → 卡片 → 按钮 → 工作流流程」完整链路；卡片链深度 ≥3 与循环引用回归。

## 8. 风险

- **范围大**：完全重构（领域/存储/API/前端/运行时），建议按「数据模型 → 运行时 → 管理 API → 前端」分阶段落地；
- **返回链**：深链返回按钮由运行时生成，需保证来源记录在会话内可靠（按 chat 缓存来源栈即可）；
- **卡片删除**：被引用卡片删除需引用检查，避免运行时出现悬空 `card_id`（保存时校验 + 删除时校验双保险）。
