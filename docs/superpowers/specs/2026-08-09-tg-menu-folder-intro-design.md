# 主键盘：每层说明文案 + 后台树编辑

## 1. 背景与目标

已有关系表树（文件夹 + 挂载 Case + 返回）。缺口：

1. 进文件夹时消息正文只有文件夹名，无法配置竞品式「文案 A / 进夹换文案 B」
2. 管理台「按钮 / 挂载 Case / 添加子项」不像 Telegram 文件夹，运维难懂

**目标（本切片）：**

- 每个文件夹可配 **本层说明**；Bot 进该层时消息上方展示该说明（无则回退为名字）
- 管理台左边改为 **可展开树**；右边用直白话编辑「这一层」
- **⬅️ 返回** 继续用现有逻辑（回上一层 / 根回主菜单）

**非目标：** 两列按钮排版、进夹时 edit 同一条消息、自定义「✍️ 提示词」类特殊按钮、多 Bot。

## 2. 产品行为（Telegram）

点进文件夹 `F`：

```
[本层说明，多行；空则只用 F 的显示名]

[本层挂载的 Case 按钮…]
[📁 子文件夹…]
[⬅️ 返回]
```

- 「图片」层的说明 = 文案 A  
- 「脱衣/换装」层的说明 = 文案 B  
- 返回：有父 → 父层；无父（根文件夹）→ 主菜单  

## 3. 数据

在现有 `tg_menu_items`（或等价领域 `MenuNode`）上增加：

| 字段 | 说明 |
|------|------|
| `intro_text`（或 `body_text`） | 可空；本层 Inline 消息正文；仅对 `kind=folder` 有意义（其它 kind 可忽略或禁止填写） |

校验：长度上限（建议 ≤ 3500，留 Telegram 余量）；无则合法。

迁移：旧行该列为空 → 行为与现网一致（只用 label）。

API 树 JSON 增加 `intro_text`；PUT 整树替换语义不变。

## 4. Bot

`showMenuFolder`：

- 消息 `text` = `trim(intro_text)`，若空则用 `label`
- 按钮顺序建议：**先 Case，再 📁 子文件夹，再返回**（更接近竞品；若实现简单可保持现状并在计划中写明）
- 返回 callback 不变（`mb:`）

## 5. 管理台（方案 A）

### 左边：树

- 根项为底部键盘各键；文件夹可展开/折叠显示子文件夹
- 选中节点 → 右边编辑该节点
- 文案：「主键盘」页说明改为类似：先选一层，再写本层说明和模板

### 右边：只编这一层（直白话）

| UI 文案（中文） | 对应字段 |
|-----------------|----------|
| 按钮上显示的名字 | `label` |
| 本层说明 | `intro_text`（多行；仅文件夹显示） |
| 本层模板 | `case_ids`（仅文件夹） |
| 下面的分类 | `children` 列表 +「加一个分类」 |
| 启用 | `enabled` |
| 行 / 列 | 仅根项显示 |

去掉或弱化难懂词：「挂载 Case」「添加子项」「按钮」列表标题 → 改为「目录」等。

类型：根层仍可选文件夹 / 仅提示 / 回复图文等；子层在文件夹下仍只允许文件夹。

## 6. 测试要点

- domain：folder 可带 intro；过长拒绝
- persistence / API：读写 `intro_text`
- channel/tg：有 intro 时消息正文为 intro；空则 label；返回仍回父层
- admin：i18n 新文案；树展开与「加一个分类」

## 7. 决策记录

| 决策 | 选择 |
|------|------|
| 后台信息架构 | A：左边真树 |
| 说明字段 | 每文件夹 `intro_text` |
| 进夹刷新方式 | 仍发新消息（不 edit） |
| 返回 | 沿用现有 |
