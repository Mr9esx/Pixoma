# Telegram Bot 交互配置设计

## 1. 目标

把流程阶段、任务通知、平台兜底和公开命令的文案放到一个可维护的配置面里。文案按业务场景组织；主键盘和卡片仍由现有菜单编辑器维护，不在本页重复编辑。

页面不做三层布局，不使用 Tab，不引入新的菜单/卡片编辑器。所有可编辑内容以表格为主。

## 2. 范围

**做**

- 保留并扩展现有 `text_templates` 渠道覆盖机制。
- 给模板增加分组元数据，后台按业务场景分区展示。
- 覆盖现有全部模板，避免升级后丢文案。
- 新增工作流阶段按钮和预览提示模板。
- 单页展示工作流阶段、任务通知、平台与会话、公开命令。

**不做**

- 不改主键盘、卡片消息和卡片按钮的数据结构。
- 不做新的菜单编辑器。
- 不把 `/confirm`、`/skip`、`/exit` 暴露为公开命令。
- 不做通用命令注册表、命令别名和权限配置。
- 不把日志、HTTP 管理端错误或开发者错误纳入文案模板。

## 3. 信息结构

页面从上到下分四个分区。

| 分区 | 内容 |
| --- | --- |
| 工作流阶段 | 预览、输入、确认、已提交的正文、按钮和触发动作 |
| 任务通知 | 当前已接入的成功、失败、取消事件和会话终止 |
| 平台与会话 | 欢迎、选择模板、退出完成、未完成会话、菜单兜底 |
| 公开命令 | `/start`、`/help` 两类稳定入口 |

### 工作流阶段

| 阶段 | 模板 | 默认值 |
| --- | --- | --- |
| 预览 | `preview_hint_label` | `预览说明：` |
| 预览 | `preview_mock_hint` | `（mock）确认后将返回一张示例图` |
| 预览 | `button_start_case` | `▶ 开始 Case` |
| 输入 | `input_prompt` | `填写参数 {{ progress }}：请输入「{{ key }}」` |
| 输入 | `input_invalid_number` | `请输入合法数字，例如 42` |
| 输入 | `input_invalid_boolean` | `请输入 true 或 false` |
| 输入 | `button_skip` | `跳过` |
| 输入 | `button_exit` | `✕ 退出` |
| 确认 | `confirm_run` | `输入完成，确认执行？` |
| 确认 | `button_confirm_run` | `✅ 确认生成` |
| 确认 | `button_exit` | `✕ 退出` |
| 已提交 | `submit_started` | `已提交，正在生成… task={{ task_id }}` |

### 任务通知

| 事件 | 模板 | 默认值 |
| --- | --- | --- |
| 成功 | `workflow_done` | `✅ 工作流完成\ntask={{ task_id }}` |
| 成功后引导 | `workflow_done_followup` | `还要继续？点菜单再选一个工作流。` |
| 失败 | `task_failed` | `❌ 任务执行失败\ntask={{ task_id }}\n状态：{{ status }}\n{{ error_msg }}` |
| 取消 | `task_cancelled` | `任务已取消\ntask={{ task_id }}` |
| 会话终止 | `session_terminated` | `该工作流已被管理员删除，当前会话已结束。` |

### 平台与会话

| 场景 | 模板 | 默认值 |
| --- | --- | --- |
| 主菜单标题 | `welcome` | `欢迎使用 ComfyUI Bot\n请选择功能：` |
| 选择模板 | `select_template` | `请选择模板：` |
| 退出完成 | `exit_done` | `已退出当前 Case，可以重新选择。` |
| 未完成会话 | `unfinished_session` | `你有一个未完成的工作流，先退出再重新开始。` |
| 菜单动作未开放 | `menu_action_placeholder` | `暂未开放` |
| 菜单更新 | `menu_updated` | `菜单已更新，请使用下方新按钮。` |

### 公开命令

| 命令 | 动作 | 模板 |
| --- | --- | --- |
| `/start` | `navigation.main` | 无独立文案 |
| `/help` | `navigation.help` | `help` |

`help` 默认值：`帮助：点下方按钮选功能。菜单更新后发 /menu 刷新。`

`/confirm`、`/skip`、`/exit` 依赖当前流程状态，不进入公开命令配置；它们对应工作流阶段按钮。

## 4. 数据与渲染

- 存储继续使用 `text_templates`，不新增表。
- `text.Spec` 增加 `Groups` 元数据，用于后台分区展示。
- 一个 key 可以出现在一个主分区；如后续需要在多个场景展示，仍只保存一条数据。
- 渲染顺序保持：渠道覆盖 → 平台默认 → 内置默认。
- 渠道或平台模板保存为空时删除覆盖，回到上一级默认。

新增 key：

- `preview_hint_label`
- `preview_mock_hint`
- `button_start_case`
- `input_invalid_number`
- `input_invalid_boolean`
- `button_skip`
- `button_confirm_run`
- `button_exit`
- `session_terminated`

## 5. 后台页面

- 页面标题：图片生成交互配置。
- 顶部提供「平台默认 / 当前渠道」作用域切换。
- 页面主体是一页四个表格分区，不使用 Tab、左侧导航和右侧 Telegram 预览。
- 表格列保持简单：模板 / 事件 / 阶段、文案、变量或动作。
- 菜单和卡片入口不进入本页面。

## 6. 验收

1. 现有模板全部可见，默认值与当前行为一致。
2. 工作流按钮、预览提示和会话终止可以配置。
3. 修改平台默认后，未单独覆盖的渠道使用新默认。
4. 修改渠道覆盖后，只有该渠道生效。
5. 清空覆盖后，正确回退到平台默认或内置默认。
6. 主键盘、卡片消息和卡片按钮仍只由现有菜单编辑器控制。
7. 页面无 Tab、无三栏布局，菜单编辑器相关代码不变。

## 7. 测试

- `text`：新增 specs、分组元数据、默认渲染、空值回退、Seed 包含新 key。
- `capability/open_case`：预览、输入、确认、提交阶段的文案和按钮读取渠道模板。
- `channel/tg`：任务成功、失败、取消、会话终止和平台兜底读取渠道模板。
- 后台：文案配置页按四个分区渲染，现有菜单编辑器挂载点和交互不变。
