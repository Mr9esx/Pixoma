# Pixoma Studio UI/UX 设计

## 1. 体验目标

Studio 同时承载对话、创作路径和资产上下文。界面必须持续回答四个问题：

1. Agent 正在做什么，是否仍在运行？
2. 当前创作由哪些阶段、操作和资产组成？
3. 哪些内容属于可复用资产，实际使用的是哪个版本？
4. 当执行需要权限、失败或断线时，用户下一步该做什么？

Flow 不承担 Trace 职责。Flow 面向创作和组织，Trace 面向执行事实和排障。

## 2. 设计系统约束

- 使用 Pixoma 设计系统语义令牌，不新增裸色值。
- 组件优先使用现有 shadcn/ui：Button、Tabs、Dialog、Drawer、Sheet、Select、DropdownMenu、Tooltip、ScrollArea、ResizablePanel、Command、Card、Badge、Input 和 Textarea。
- 状态结果统一由领域状态计算；健康状态遵循绿色/黄色两档规则。
- 状态文案使用「已启用 / 已停用」，动作使用「启用 / 停用」。
- 不用大面积渐变、玻璃拟态和装饰性营销组件。
- 图标按钮必须有 Tooltip 和 `aria-label`。

## 3. 导航与路由

### 3.1 后台入口

普通后台菜单只新增：

```text
创作 Studio
```

点击进入 `/studio`，切换为独立 Studio Shell。

### 3.2 Studio 左栏

从上到下：

```text
Pixoma Studio
← 返回后台

＋ 新对话
▣ 资产库

搜索对话
最近对话
...

当前用户
```

交互规则：

- 「新对话」立即创建本地空态，第一条消息发送时再持久化 Session。
- 「资产库」为一级切换项，选中后右侧全部内容进入资产库模式。
- Session 历史显示标题、更新时间和状态；不显示资产数量等次要信息。
- 运行中显示动态状态；等待审批和失败使用黄色问题状态；已完成未查看显示数量 Badge。
- 本期不提供归档和删除菜单。

### 3.3 路由

```text
/studio
/studio/sessions/:sessionId
/studio/assets
/studio/assets/:assetId
```

路由切换不得取消后台 Run。回到 Session 时恢复滚动位置、选中 Tab 和 Flow 视口。

## 4. Session 页面布局

桌面布局：

```text
┌──────────────┬──────────────────────────┬──────────────────────────────┐
│ Studio 左栏  │ Chat                     │ 创作 Flow / Session 资产     │
│              │                          │                              │
│ 返回后台     │ 标题 / 运行状态 / Trace  │ Tab + 工具栏                 │
│ 新对话       │                          │                              │
│ 资产库       │ 消息                     │ 可编辑画布或资产列表         │
│ 历史         │                          │                              │
│ 用户         │ Composer                 │                              │
└──────────────┴──────────────────────────┴──────────────────────────────┘
```

- 左栏固定宽度。
- Chat 与工作台使用 ResizablePanel。
- 工作台允许折叠，折叠后 Chat 占用剩余宽度。
- 小屏时左栏变为 Drawer，工作台变为右侧 Sheet；不在同一屏强塞三栏。

## 5. Chat

### 5.1 Header

Header 仅包含：

- 可点击编辑的 Session 标题。
- 当前 Run 状态。
- 后台运行提示。
- Trace 按钮。
- 窄屏工作台入口。

Header 不放模型、Skill 和权限选择器。

### 5.2 消息

用户消息：

- 文本。
- 本轮引用资产 Chips。
- 发送时间和失败重试状态。

Assistant 消息：

- 流式正文。
- 可折叠 Thinking/Reasoning。
- 精简 Tool 状态条。
- 审批卡片。
- 新资产快捷卡片。
- 面向用户的错误与恢复建议。

Tool 卡片只显示名称、状态和结果摘要。完整参数、模型、Token、重试和错误进入 Trace Drawer。

### 5.3 Thinking

- `hidden`：不渲染内容。
- `collapsed`：显示「已思考 N 秒」或「思考过程」，默认收起。
- `expanded`：默认展开，用户仍可收起。
- 模型没有返回可展示内容时，只显示短暂运行状态，不生成空卡片。

### 5.4 Composer

结构：

```text
引用资产 Chips
┌────────────────────────────────────────────┐
│ 描述你想继续完成什么…                     │
│                                            │
│ ＋资产  Skill  模型  请求批准 ▾       发送 │
└────────────────────────────────────────────┘
```

行为：

- `＋资产` 打开 Session 资产与个人资产库选择器，也支持上传。
- `Skill` 使用 Command 列表，支持显式选择和取消。
- `模型` 只列出 `enabled && agent_enabled && healthy` 的主 Agent 模型。
- 权限菜单为「请求批准 / 帮我批准 / 完全访问」。
- “完全访问”首次选择显示风险 Dialog。
- 运行中发送按钮变为停止按钮，输入框禁用。
- 等待审批或补充输入时，输入框根据中断类型恢复。
- 模型或权限切换只影响下一次 Run。

### 5.5 审批卡片

请求批准：

- 展示准备执行的动作、目标系统、关键参数摘要和风险原因。
- 提供「批准」「拒绝」。
- 不提供旧方案中的“Session 内允许一次/长期允许”按钮；权限范围由 Composer 三档模式管理。

帮我批准：

- 展示自动审核状态：审核中、已批准、已拒绝、需要你确认、超时。
- 自动审核失败时失败关闭，不执行动作。

## 6. 创作 Flow

### 6.1 定位

Flow 是 Session 的可编辑 SOP 与资产 Road。它可以先规划后执行，也可以随对话和资产产生自动生长。

### 6.2 工具栏

- 新增阶段。
- 新增计划。
- 撤销。
- 重做。
- 整理布局。
- 适应画布。
- 缩小 / 放大。

工具栏不提供“运行整张 Flow”。Flow 不是可执行工作流编辑器。

### 6.3 阶段节点

阶段使用自定义父节点：

- 左上角显示两位编号。
- 标题和一行说明可编辑。
- 显示完成项计数，不显示 Trace 事件数。
- 可拖动、调整尺寸和排序。
- 子节点可在阶段之间拖动。

示例：

```text
01
立住角色
上传或生成三视图，锁定角色的样子。
```

### 6.4 计划、操作与资产节点

计划节点：

- 标题、说明、待办状态。
- 可以由用户或 Agent 创建。
- 后续可绑定为模型生成、工作流或 MCP 操作。

操作节点：

- 显示操作名称、类型、状态、输入数和输出数。
- 状态：计划中、运行中、等待、完成、失败、取消。
- 点击打开节点详情。
- 允许“再次执行”，但不会覆盖旧 Run。

资产节点：

- 图片使用缩略图；文本显示类型图标和摘要。
- 显示名称、固定版本和来源。
- 可以选择当前采用版本。
- 双击打开资产详情。

### 6.5 连线

- Handle 默认弱化，节点选中或开始连接时显示。
- Input、Output、Reference 使用相同基础边样式，通过标签区分语义。
- 禁止自连接、重复边和无效类型连接。
- 阶段排序不创建边。

### 6.6 自动布局与手动布局

- 空 Flow 根据对话时间顺序自上而下创建阶段。
- 新节点插入当前阶段的空闲区域。
- 用户移动过的节点标记为手动布局，后续自动整理不改变其位置。
- “整理布局”执行前生成可撤销快照。
- 新增节点后只调整新增区域，不自动 `fitView` 打断用户当前视角。

### 6.7 删除语义

- 删除资产节点：仅从 Flow 移除，不删除 Asset。
- 删除操作节点：仅从 Flow 移除，不删除 Run Trace。
- 删除阶段：询问“同时移除子节点”或“移动到未分组”。
- 删除与断开连接均支持撤销。

### 6.8 节点详情

在工作台内打开覆盖式详情面板：

- 标题和说明。
- 输入参数摘要。
- 输入与输出资产。
- 工作流或模型信息。
- 采用的资产版本。
- 再次执行。
- 查看执行记录。

“查看执行记录”打开 Trace Drawer，不把 Trace 数据铺在 Flow 上。

## 7. Session 资产 Tab

### 7.1 内容

- Session 内生成、上传、手动创建或从资产库引用的资产。
- 按阶段、类型和来源筛选。
- 网格和列表视图。
- 当前采用版本标记。

### 7.2 操作

- 查看、下载和重命名。
- 编辑文本并保存新版本。
- 查看版本历史。
- 添加到 Flow。
- 保存到个人资产库。
- 查看来源操作和 Trace。

普通聊天文本、提示词、日志和标量参数不出现在资产 Tab。

## 8. Trace Drawer

入口：

- Chat Header 的「Trace」。
- Tool 状态条的「查看详情」。
- Flow 操作节点的「查看执行记录」。

内容按 Run 与时间顺序组织：

- 用户消息。
- Agent 配置和模型快照。
- 上下文组成摘要。
- Thinking/Reasoning。
- 模型请求与响应状态。
- Tool Call 和结果。
- 审批。
- 工作流外部任务。
- 资产创建。
- 错误、重试和恢复。
- Token、耗时和费用估算。

默认展示摘要；原始 JSON 放在二级折叠区并脱敏。

## 9. 资产库模式

### 9.1 页面结构

```text
Studio 左栏 | 文件夹树 | 资产列表 / 网格 | 资产详情
```

Studio 左栏保持可见。资产库使用 Chat 与工作台的全部内容宽度。

### 9.2 顶部操作

- 搜索。
- 类型与来源筛选。
- 创建资产。
- 上传资产。
- 新建文件夹。

### 9.3 创建资产

本期支持：

- Markdown。
- 纯文本。
- JSON。
- 文件上传。

从 Session 保存的资产不复制 Blob，只创建资产库引用。

### 9.4 资产详情

- 预览。
- 当前版本与版本历史。
- 来源类型。
- 来源 Session。
- 所在文件夹。
- 元数据与文件信息。
- 「用于创作」。

「用于创作」可以选择已有 Session，或创建一个已引用该固定版本的新 Session。

## 10. AI 设置页面

四个页面位于现有设置 Shell 内，共用 AI 能力二级导航。

### 10.1 模型连接

列表显示：名称、协议、模型数、启停和健康状态。

详情包含：

- Base URL、认证和自定义 Header。
- 测试连接。
- 同步模型与手动添加模型。
- 模型能力、启用状态和“允许 Agent 使用”。
- 文本、流式、Tool、视觉与图片生成测试。

密钥保存后只显示掩码，不提供回显按钮。

### 10.2 Agent 设置

- 只读 Pixoma 运行契约摘要。
- 管理员 Agent 指令编辑器。
- 默认主模型、标题模型、总结模型、生图模型、Reviewer 模型。
- 默认权限模式和允许用户选择的模式。
- Thinking 显示与 Reasoning Effort。
- 最大步骤、超时、并发与上下文预算。
- 测试对话与版本信息。

### 10.3 Skills

- 列表、启停和当前版本。
- 名称、描述和 `SKILL.md` 编辑。
- References 与 Assets 文件。
- 测试对话。
- 不显示脚本、依赖关系和 Tool 权限矩阵。

### 10.4 MCP 连接器

- 仅可选择 Streamable HTTP。
- 系统级认证配置。
- 连接测试和能力发现。
- Tool、Resource、Prompt Tab。
- Tool 调用策略：自动、进入审批、禁止。
- 最近调用和错误。
- 不显示 `stdio` 和用户级 OAuth 选项。

## 11. 页面与运行状态

### 11.1 新 Session

```text
新对话
→ 空态展示能力提示
→ 用户发送首条消息
→ Session 与消息落库
→ 主 Run 启动
→ 标题异步生成
```

### 11.2 工作流后台运行

```text
Agent 调用工作流
→ Flow 创建或更新操作节点
→ Run waiting_external
→ 用户离开页面
→ 服务端继续
→ 完成后生成资产并更新 Flow
→ 用户回来恢复 Snapshot 与事件
```

### 11.3 审批

```text
Tool 命中审批规则
→ 保存 Checkpoint
→ Chat 显示审批卡片
→ Run waiting_approval
→ 批准 / 拒绝 / Reviewer 决策
→ 从同一 Checkpoint 恢复
```

### 11.4 取消

- 模型和可取消 Tool 立即终止。
- 外部工作流无法立即停止时显示“取消请求中”。
- 最终产物仍记录，但不会自动标为 Flow 的有效输出。

### 11.5 失败

- Chat 显示发生了什么和可执行的下一步。
- Flow 操作节点保留失败状态。
- 已产生的资产不删除。
- Trace 保存原始错误、重试和恢复信息。

## 12. 后台通知

- Session 历史持续显示运行状态。
- Studio 菜单显示待审批和完成未查看数量。
- Pixoma 页面仍打开时显示完成或失败 Toast。
- 不申请系统通知权限。

## 13. 响应式与可访问性

- 推荐桌面宽度不小于 1280px。
- 1024–1279px：Studio 左栏可折叠，Chat 与工作台仍可调整。
- 小于 1024px：左栏使用 Drawer，工作台使用 Sheet。
- 键盘支持节点选择、删除、撤销/重做、Tab 切换和 Composer 操作。
- Interactive elements inside Flow nodes 使用 `nodrag`，滚动区使用 `nowheel`。
- reduced motion 下关闭脉冲、自动滚动和布局动画。

## 14. 高保真原型验收脚本

原型必须支持本地状态流转：

1. 从单一后台入口进入 Studio。
2. 新建 Session 并发送漫画创作目标。
3. 标题自动生成。
4. 在 Composer 切换模型和三档权限模式。
5. 展开或收起思考过程。
6. 生成并编辑 `story.md`，保存为新版本。
7. Flow 自动生成三个阶段，并允许拖动阶段或节点。
8. 新增计划节点和阶段。
9. 模型直接生成角色图，形成操作与资产节点。
10. 工作流等待审批、后台运行并生成分镜资产。
11. 切到资产库时后台进度继续。
12. 从资产库返回 Session 后恢复状态。
13. 删除 Flow 节点时展示“不删除资产”的说明。
14. 从操作节点打开 Trace Drawer。
15. 进入设置中的模型、Agent、Skill 和 MCP 页面查看配置状态。

## 15. 文案原则

- 说清当前状态和用户下一步，不使用含糊的“处理中”。
- 错误文案包含对象和恢复入口。
- 风险文案不恐吓，但明确说明影响范围。
- 后台运行使用「任务会继续运行，可以离开此页面」。
- 保存到资产库使用「保存到资产库」，不使用“发布”或“同步”。
