# Pixoma Studio UI/UX 设计

## 1. 设计目标

AI 创作页面同时承载对话、执行过程和资产上下文。界面需要让用户始终知道三件事：Agent 正在做什么、使用了哪些输入、产出了哪些可继续使用的资产。

页面遵循 Pixoma 设计体系：neutral 语义令牌、单一陶土色点缀、表面无投影、组件优先复用 shadcn/ui、中文动作文案、920px 以下重排。

## 2. Studio Shell

### 2.1 桌面布局

```text
┌─────────────┬────────────────────────────┬─────────────────────────┐
│ 240px       │ minmax(420px, 1fr)         │ minmax(440px, 46vw)     │
│ Studio 导航 │ Chat                       │ Flow / 资产              │
└─────────────┴────────────────────────────┴─────────────────────────┘
```

- 三栏均使用完整视口高度。
- 中栏和右栏之间允许拖动调整宽度。
- 分隔只使用细线，不增加卡片投影。
- Chat Composer 固定在中栏底部。
- 右栏 Tab 与内容固定在独立滚动区。

### 2.2 窄屏

- 920px 以下改为单面板。
- 顶部使用「对话 / 执行流 / 资产」Tab 切换。
- Session 历史从左侧 Sheet 打开。
- 不产生横向滚动。

## 3. 左栏

从上到下：

1. 「返回后台」。
2. 「新对话」主操作。
3. 对话搜索。
4. 历史 Session 列表。
5. 用户信息。

历史项状态：

- 运行中：显示 Spinner 与「运行中」。
- 等待审批：黄色 StatusDot 与「等待确认」。
- 已完成：不显示额外状态。
- 失败：黄色 StatusDot 与「需要处理」。

健康与警告沿用项目状态规范，不使用红色健康档位。危险操作本期不进入 Session 历史菜单。

## 4. Chat 中栏

### 4.1 Header

- 标题占主位置，先显示「新对话」，首条输入后异步替换。
- 模型选择使用紧凑 Select。
- 运行状态使用小号状态行。
- 不放归档、删除等本期无关动作。

### 4.2 消息流

使用 assistant-ui Thread、Message、Composer 和 Tool UI。消息区包含：

- 用户消息。
- Agent 文本回答。
- 计划摘要。
- Tool 状态卡片。
- 资产附件卡片。
- 审批卡片。
- 失败与恢复卡片。

不展示原始 Chain of Thought。Flow 只展示面向用户的活动摘要、输入输出和 Trace 元数据。

### 4.3 Composer

主输入使用多行输入框。附加入口：

- 上传文件。
- 从资产库选择。
- 从当前 Session 选择。
- 查看已附加资产。

发送运行中变为「停止」。后台 Run 不因路由切换停止。

## 5. 右栏

### 5.1 执行流

React Flow 节点：

- Message：本次用户输入。
- Model：模型调用与完成状态。
- Tool：Skill、MCP、Asset Tool。
- Workflow：Pixoma 工作流及关联 Task。
- Approval：等待、批准、拒绝。
- Asset：输入和输出资产。

节点只展示名称、类型、状态和耗时。点击节点打开右侧内嵌详情或 Sheet，避免把大段参数塞进画布。

连线语义：

- `consumes`：资产或消息作为输入。
- `invokes`：模型调用 Tool。
- `produces`：步骤生成资产。
- `derives`：资产由其他资产派生。

### 5.2 资产

按「上下文 / 本次输入 / 本次输出 / 其他产物」分组。资产卡片支持：

- 预览。
- 固定或取消固定。
- 作为下一次输入。
- 编辑文本资产。
- 保存到资产库。
- 查看来源。

## 6. 关键状态流转

### 6.1 首次对话

```text
点击新对话
→ 输入创作目标
→ 消息立即写入 Session
→ Run 启动
→ 标题并行生成
→ Flow 出现 Message 与 Model 节点
```

### 6.2 文本资产编辑

```text
Asset 节点完成
→ Chat 与资产 Tab 同时出现资产
→ 打开 Markdown 编辑器
→ 保存
→ 创建新版本
→ Session 引用切换到新版本
```

### 6.3 审批

```text
Tool 请求越过权限边界
→ Run 进入等待状态
→ Chat 与 Flow 同时显示审批
→ 允许一次 / Session 允许 / 拒绝
→ AG-UI resume 恢复原 Run
```

### 6.4 后台运行

```text
Run 运行中
→ 用户切换路由或关闭页面
→ 服务端继续执行
→ 用户重新打开 Session
→ 加载状态快照
→ 订阅增量事件
→ UI 恢复到最新状态
```

## 7. 资产库页面

### 7.1 页面结构

左侧为文件夹树，右侧为资产列表。顶部提供搜索、类型和来源筛选，以及「创建资产」「上传资产」。

### 7.2 创建资产

第一期支持：

- 新建 Markdown。
- 新建纯文本。
- 新建 JSON。
- 上传文件。

创建后直接进入编辑或详情页。

### 7.3 资产详情

桌面使用主预览 + 详情侧栏：

- 主区展示图片、文本、音视频或通用文件摘要。
- 侧栏展示来源、版本、关联 Session、血缘和文件夹。
- 点击关联 Session 可进入对应 AI 创作页面。

## 8. 原型覆盖场景

高保真原型使用本地假数据覆盖：

1. 新建漫画创作 Session。
2. 首条消息后标题自动更新。
3. Agent 生成 `story.md`。
4. 生图模型直接生成角色概念图，Flow 展示提示词输入和图片资产输出。
5. 编辑并保存 `story.md v2`。
6. 请求并批准分镜工作流。
7. 模拟后台运行并生成分镜图。
8. 切换 Flow / 资产 Tab。
9. 点击资产查看来源和版本。
10. 保存资产到资产库。
11. 在资产库创建文件夹、上传或手动创建资产、查看关联 Session。

## 9. 可访问性与状态

- 所有图标按钮提供可见 Tooltip 和 `aria-label`。
- 键盘可操作 Tab、Session 列表、Composer 和节点详情。
- 加载、空态、错误态和等待审批状态完整。
- 动效只用于流式输出、节点状态和面板切换；支持 reduced motion。
- 触屏命中区不小于 44px。
