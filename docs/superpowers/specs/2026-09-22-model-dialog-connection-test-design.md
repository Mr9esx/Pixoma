# 添加模型弹窗测试连接设计

## 目标

在“添加模型”弹窗中提供一个不落库的测试按钮，用当前表单配置发送一次最小探测消息，帮助管理员在保存前确认协议、地址、模型 ID 和 API Key 是否可用。

## 方案

新增 `POST /api/v1/studio/models/test` 接口。请求体复用创建模型所需字段，但服务端只在内存中构造 `ResolvedModelConfig`，调用现有 `ModelConnectionTester` 的最小消息检查，不创建数据库记录、不返回 API Key 或模型供应商原始密钥。成功响应沿用已有 `success` 与 `latency_ms` 字段；失败错误经过现有脱敏逻辑处理。

前端 `ModelDialog` 抽出创建/测试共用的配置映射。footer 左侧放置“测试连接”按钮和最近一次结果，测试期间禁用测试与保存，右侧继续显示“取消”和“保存模型”。测试按钮先触发表单原生必填/URL 校验；失败显示可读错误，成功显示耗时。修改表单后清除旧测试结果，避免结果对应错误配置。

## 验收

- 未填写必填字段时点击测试不会发起请求。
- 完整配置测试请求不会创建模型记录。
- 测试请求会发送固定的最小探测消息，并返回成功或经过脱敏的错误。
- 保存行为、已有已保存模型测试按钮和模型列表行为不变。
- Go 服务测试、前端 API 测试、弹窗契约测试通过。
