# 链路健康提示与下一步行动 交互方案

配套可交互原型：`link-health-interaction.html`（会话内嵌可视化）；本文件是交互规范文本，两者一致。

## 1. 目标

让 B 端运营打开详情页就能回答四个问题：**现在能不能用、为什么、下一步做什么、具体怎么修**。一期**不做 React Flow 全链路图**（用户决策），重心放在「人话结论 + 可执行的下一步 + 处理指引」。

## 2. 范围

- Case / Topic / 计算节点三个详情页新增「状态与关联」区块：
  1. **Header 告警**（页面头部）：异常时显示 Alert 摘要（{{name}} 当前不可用，有 N 处问题）+ 「查看处理指引 ↓」锚点
  2. **健康检查明细**（页面下方）：正常时显示绿色「链路正常」（入口、Topic、节点均就绪）确认行；异常时显示断点列表——原因 + 分类徽标（配置问题 / 运行问题）+ 行动按钮（去修）+ 处理指引（怎么处理，一行步骤）
  3. **引用列表**：上游（被谁引用）/ 下游（引用了什么）
- 全链路图（React Flow）二期评估，一期不出现。

## 3. 页面结构（三页一致）

详情页从上到下：

1. **页面 Header**（名称、状态标签）——既有。
2. **Header 告警**（新增，仅异常时出现）：一行摘要 + 「查看处理指引 ↓」，点击滚动到下方健康区块；正常时 Header 不出现。
3. **状态与关联**（新增）：正常时绿色「链路正常」确认行；异常时断点列表（原因 → 分类徽标 → 行动按钮 → 怎么处理）+ 引用列表（上游 / 下游表格化列表，分页 + 可点击跳转）。
4. **既有模块**（工作流配置 / 处理流程 / 指标面板）——位置不变；原「关联入口」独立区块已移除，由「状态与关联」上游列表承担。

### 处理流程（任务分流编辑器）

- 默认**预览模式**：只读画布（不可拖节点、不可连线、不可加分支），隐藏顶栏（校验条）与右侧 Topic 池。
- 画布右上角「编辑处理流程」按钮 → 打开**全屏编辑弹窗**：完整编辑器（顶栏校验 + Topic 池 + 保存按钮）。

## 4. 状态语义

| 状态 | 含义 |
|---|---|
| `ok` | 链路正常，该实体所有依赖齐全且可用 |
| `warn` | 链路异常，存在 1+ 断点 |
| `bad` | 实体缺失（数据异常兜底，正常不出现） |

### 断点分类

| 分类 | 徽标 | 含义 | 用户预期 |
|---|---|---|---|
| 配置问题 | 蓝 | 改配置可修（没绑 Topic / 没挂入口 / 没配路由） | 修完立即生效 |
| 运行问题 | 红 | 环境问题（节点停用 / 离线） | 修完需等在线 |

### 断点规则与行动

| 视角 | 断点 | 分类 | 行动 | 处理指引（示例） |
|---|---|---|---|---|
| 工作流 | 没有渠道菜单入口，用户不可达 | 配置 | 去添加入口 | 在渠道菜单编辑器中添加「打开工作流」入口，选择该工作流，保存并发布 |
| 工作流 | Topic {{topic}} 没有在线计算节点 | 运行 | 去管理节点 | 确认该 Topic 有计算节点订阅且在线；检查 agent 心跳与 Comfy 服务 |
| Topic | 没有工作流路由到该 Topic | 配置 | 去配置路由 | 在该工作流的处理流程中添加路由规则，把条件指向该 Topic |
| Topic | 没有计算节点订阅该 Topic | 配置 | 去订阅 Topic | 在计算节点详情中勾选该 Topic 订阅并保存 |
| Topic | 订阅计算节点全部离线 | 运行 | 去管理节点 | 检查 edge-agent 进程、控制面网络与 Comfy 服务 |
| 计算节点 | 该计算节点没有订阅任何 Topic | 配置 | 去编辑节点 | 在计算节点编辑弹窗勾选至少一个 Topic 订阅 |
| 计算节点 | 没有工作流把任务派给该节点 | 配置 | 去配置路由 | 在该工作流的处理流程中配置路由规则，让任务经订阅的 Topic 派给该节点 |
| 计算节点 | 计算节点未就绪（停用或离线） | 运行 | 检查节点 | 确认已启用；仍离线则检查 agent 进程与网络，等心跳恢复 |

文案模板：**原因（人话）→ 分类徽标 → 行动链接 → 怎么处理（一行步骤）**。例如「没有渠道菜单入口，用户不可达 `[配置]` 去添加入口 → 怎么处理：在菜单编辑器中添加「打开工作流/Case」入口并发布」。

## 5. 交互清单

| 交互 | 行为 |
|---|---|
| Header 告警 | `role="alert"`，仅异常时显示；「查看处理指引 ↓」锚点滚动到下方健康区块 |
| 断点行动按钮 | 跳转到对应配置/管理页（`Link` 导航，支持 Cmd/Ctrl+点击） |
| 处理指引 | 断点下方一行人话步骤，默认展示；二期改为可折叠（`details/summary`） |
| 引用列表 | 表格化列表（名称 + 状态标签），标题带计数；每页 10 条，底部「上一页 / 下一页 + 页码」分页；行点击跳转对应实体详情页 |

## 6. 视觉编码

- Header 告警：琥珀色 Alert（异常时）；正常时 Header 不出现告警。
- 断点分类徽标：蓝 = 配置问题，红 = 运行问题。
- 视觉与既有页面一致：区块头用 `SectionHead`，断点/引用用紧凑边框列表，不自造大 padding 卡片。
- 颜色不单独承担语义，文字标签始终显示。

## 7. 键盘与可达性

- 行动按钮与引用胶囊使用原生 `<Link>`，键盘可达、焦点样式可见。
- 结论横幅 `role="status"`；断点列表为普通列表。
- 尊重 `prefers-reduced-motion`。

## 8. 空态与加载态

- **加载中**：状态与关联区块显示骨架占位（与既有 LoadingSkeleton 一致）。
- **数据错误**：区块内显示 ErrorBanner + 重试。
- **引用为空**：列表显示「无」，结论横幅仍给出断点原因与行动。
- **节点全部离线**：Case/Topic 横幅变 warn，断点标注「运行问题」+ 行动，不隐藏。

## 9. 与既有模块的关系

- **ConfigChain**：工作流页已移除（与「状态与关联」重复，且其内部「投放/执行」判定曾不一致），状态与关联统一承担健康结论与行动；Topic 页暂保留，待评估。
- 一期不引入 `@xyflow/react`；全链路图在 Phase 2 评估（届时用确定性分层坐标 + `fitView`/`Controls`，不引入 task-flow 编辑器布局 hook）。
