# Pixoma Studio PRD

## 1. 产品定义

Pixoma Studio 是 Pixoma 后台中的 AI 创作工作区。它以 Session 组织长期创作过程，以 Asset 记录可复用产物，以 Agent 协调模型、工作流、Skill 与 MCP 能力，并用 Flow 展示每次运行的输入、执行步骤、审批和输出。

Pixoma Studio 不是聊天版工作流启动器。核心闭环是：

```text
提出目标 → 建立上下文 → Agent 规划 → 调用能力 → 生成资产
       → 查看与编辑 → 继续迭代 → 保存到资产库 → 跨 Session 复用
```

## 2. 目标用户

第一期面向已登录的 Pixoma 后台用户。管理员维护系统级模型连接；后台用户可在 Session 中选择可用模型，但不能读取模型密钥。

典型角色：

- 创作者：通过自然语言完成多步骤创作。
- 工作流设计者：组合和验证工作流输入输出。
- 运营人员：复用资产、批量生成内容、追踪运行结果。
- 管理员：维护模型连接、MCP 连接器、Skill 与权限策略。

## 3. 产品价值链

```text
创作意图
  ↓
自然语言理解与上下文组织
  ↓
能力选择：模型 / 工作流 / Skill / MCP
  ↓
可控执行：审批 / 后台运行 / 重试 / 恢复
  ↓
资产产出：文档 / 图片 / 音频 / 视频 / 结构化数据
  ↓
资产沉淀：版本 / 血缘 / 文件夹 / 跨 Session 复用
```

Pixoma 的差异化不在单次回答，而在“对话、执行和资产”共同形成可追溯的创作过程。

## 4. 信息架构

现有后台菜单新增 `Studio` 分组，放在概览入口之后、配置管理之前：

```text
Studio
├── AI 创作
└── 资产库
```

### 4.1 AI 创作

进入独立的 Studio Shell，替换普通后台侧栏，使用三栏布局：

```text
Studio 导航 | Chat | Flow / 资产
```

### 4.2 资产库

资产库继续使用普通后台壳层，提供文件夹、搜索、筛选、资产预览、版本、来源和关联 Session 管理。

## 5. 核心对象

### 5.1 Session

Session 是长期创作工作区，必须自动保存。它完整记录：

- 用户与 Agent 的所有消息。
- 每次模型输入与输出。
- Tool 调用参数与返回值。
- 工作流任务与状态。
- 资产引用、版本和血缘。
- 审批请求与处理结果。
- 运行错误、停止、重试和恢复记录。

这些信息同时服务历史对话恢复与 Trace 分析。

### 5.2 Agent Run

每次用户发送消息触发一个 Agent Run。Run 可以包含多个模型步骤、Tool Call、审批和异步任务。

用户切出页面后，Run 必须在后台继续执行。重新进入 Session 时，页面从服务端恢复消息、Flow、资产和运行状态，并继续接收实时更新。

### 5.3 Asset

Asset 是可复用、可引用、可追溯的创作产物。普通自然语言回答不自动成为 Asset。

支持类型：

- 文本文档：Markdown、纯文本。
- 图片。
- 音频。
- 视频。
- 结构化数据：JSON、CSV 等。
- 通用文件。

来源：

- 用户上传。
- 用户手动创建。
- Agent 生成。
- 模型原生生成。
- 工作流输出。
- Skill 输出。
- MCP 返回。
- 基于已有资产派生。

### 5.4 Session Asset 与资产库

- Session Asset 只属于当前 Session。
- 用户可把 Session Asset 手动保存到资产库。
- 资产库资产可引入任意 Session。
- 引入时记录固定版本，资产库后续更新不改变历史运行输入。
- 文本类资产支持查看、编辑和保存新版本。

资产的“来源归属”与“可见范围”分开处理：Session 生成的资产始终保留来源 Session；保存到资产库只是扩大其可见范围，不改变来源，也不复制底层文件。资产库资产被引入 Session 时只创建固定版本引用，不把资产转移给该 Session。

## 6. 用户旅程

### 6.1 漫画创作

```text
输入故事想法
→ Agent 生成 story.md
→ 用户编辑并保存 v2
→ Agent 生成角色图
→ Agent 请求运行分镜工作流
→ 用户审批
→ 工作流以 story.md v2 和角色图为输入
→ 输出分镜图
→ 用户继续生成变体
→ 选中结果保存到资产库
```

### 6.2 批量风格探索

```text
引入参考图
→ 要求生成多种风格
→ Agent 选择模型或工作流
→ 后台并行运行
→ Flow 展示各分支状态
→ 用户比较结果
→ 选择一个结果继续派生
```

### 6.3 从资料到视觉内容

```text
导入文档或通过 MCP 获取资料
→ Agent 提炼大纲
→ 生成文案资产
→ 生成配图提示词
→ 模型或工作流生成图片
→ 形成可复用的内容资产集合
```

### 6.4 工作流调试

```text
选择工作流
→ Agent 读取输入定义
→ 生成多组参数
→ 执行并比较结果
→ Trace 展示输入、任务、错误和输出
→ 用户选择下一轮参数
```

### 6.5 通用用户旅程

| 阶段 | 用户问题 | 产品触点 | 系统责任 | 用户获得的价值 |
|---|---|---|---|---|
| 开始 | 我想做什么，从哪里开始？ | 新对话、模型选择、资产引入 | 自动保存首条消息，异步生成标题 | 不需要先理解工作流结构 |
| 建立上下文 | Agent 是否理解我的资料和约束？ | Chat 附件、Session 资产 | 固定资产版本，区分本次输入与长期上下文 | 多轮创作不重复上传和解释 |
| 规划 | 接下来会发生什么？ | 计划摘要、Flow | 选择模型、工作流、Skill 或 MCP | 执行过程可预期 |
| 执行 | 是否安全，离开页面会不会中断？ | 审批卡、运行状态、后台任务条 | 策略判断、中断恢复、服务端续跑 | 可控地交给 Agent 完成耗时任务 |
| 判断结果 | 结果从哪里来，为什么失败？ | Flow 节点、Trace、资产来源 | 统一记录输入、调用、错误和输出 | 能解释、能重试、能继续迭代 |
| 继续创作 | 如何修改并用于下一步？ | 资产预览、编辑、版本、再次引用 | 保存新版本和派生关系 | 中间结果不再散落在聊天记录中 |
| 沉淀复用 | 如何带到下一次创作？ | 保存到资产库、文件夹 | 扩大可见范围，保留来源和固定版本 | 形成个人或团队创作资料库 |

### 6.6 场景覆盖判断

| 场景 | 典型能力组合 | 第一阶段覆盖 | 仍需补充 |
|---|---|---|---|
| 漫画、绘本、视觉故事 | 文本资产 + 模型生图 + 分镜工作流 | 完整覆盖核心闭环 | 角色一致性与批量审片可后续增强 |
| 海报、主视觉、商品图探索 | 参考资产 + 模型生成 + 并行工作流 | 覆盖生成、比较、派生和沉淀 | 缺少专门的对比画布与批量标注 |
| 文档到图文内容 | 上传或 MCP + 摘要 Skill + 生图 | 覆盖资料获取、文案和图片产出 | 引用出处校验需要连接器专项能力 |
| 视频与音频前期制作 | 脚本 + 分镜 + 模型原生音视频 | 架构覆盖，取决于接入的模型能力 | 时间轴编辑不在本期范围 |
| 工作流调试与参数探索 | Workflow Tool + Trace + 多组输入 | 覆盖调用、错误定位和结果资产化 | 版本间参数 diff、批量对比尚不完整 |
| 外部系统内容运营 | MCP 查询 + 外部写 Tool + 审批 | 覆盖读取、写入审批和 Trace | 定时发布、批量审批不在本期范围 |
| 跨 Session 素材复用 | 资产库 + 固定版本引用 | 完整覆盖单用户复用 | 多人协作、共享权限和评论不在本期 |
| 无人值守的周期自动化 | 调度 + Agent 后台执行 | 不作为本期目标 | 需要计划任务、通知和运行治理模块 |

结论：第一阶段适合“单个后台用户发起、过程中可离开、结果以资产沉淀”的创作任务。它能够覆盖漫画案例的完整旅程，也能泛化到图文、营销素材、模型原生媒体生成和工作流调试。团队协作、时间轴编辑、复杂批量审片和周期自动化不应被包装成第一阶段已经解决的能力。

## 7. AI 创作页面需求

### 7.1 左栏

- 返回后台。
- 新对话。
- 对话历史和搜索。
- 历史项显示标题、更新时间、运行状态、资产数量和待处理状态。
- 底部显示用户头像、名称和角色。

本期不做归档和删除。

### 7.2 Chat 中栏

Header 显示：

- 当前 Session 标题。
- 当前模型连接。
- 运行状态。

首条用户消息发送后，系统异步生成 10–20 字标题。标题生成不阻塞主 Run；失败时使用首句截断作为备用标题。

消息流支持：

- 用户与 Agent 消息。
- Agent 计划摘要。
- Tool 调用卡片。
- 工作流运行卡片。
- 资产卡片。
- 审批卡片。
- 错误、停止、重试和恢复状态。

Composer 支持：

- 文本输入。
- 上传文件。
- 从资产库选择资产。
- 选择当前 Session 资产。
- 发送与停止。

资产引用分为：

- 本次消息资产：只参与当前 Run。
- Session 上下文资产：后续 Run 默认可见。

### 7.3 右栏

使用「执行流 / 资产」Tab。

执行流：

- 默认展示最近一次 Run，可切换历史 Run。
- 展示 Message、Model、Tool、Approval、Workflow、Asset 节点。
- 状态包括未开始、运行中、等待审批、已完成、已失败、已取消。
- 点击节点查看输入、输出、模型、Tool、关联资产、错误和 Trace 时间。
- Asset 节点与资产 Tab 双向联动。

资产：

- 展示已固定资产、本次输入、本次输出、中间产物和资产库引用。
- 支持查看、编辑文本资产、保存新版本、固定到 Session、用于下一次输入、保存到资产库、查看来源链。

## 8. 资产库需求

### 8.1 文件夹

- 新建、重命名和删除文件夹。
- 删除文件夹不删除资产，资产回到「未分类」。
- 资产可进入多个文件夹，不复制底层文件。
- 支持批量移动。

### 8.2 资产列表

- 网格与列表视图。
- 搜索名称和内容摘要。
- 按类型、来源、创建时间、文件夹、是否关联 Session 筛选。
- 显示缩略图、名称、类型、版本、来源和更新时间。

### 8.3 资产详情

- 预览。
- 元数据。
- 当前版本和版本列表。
- 来源类型。
- 关联 Session。
- 关联工作流或 Tool Call。
- 输入资产与派生产物。
- 文件夹归属。

用户直接上传的资产显示「用户上传」，不要求关联 Session。

## 9. 模型与能力

### 9.1 模型连接

- 管理员维护多个系统级模型连接。
- 支持标准 OpenAI 与 OpenAI-compatible 接口。
- 支持本地和云端服务。
- Session 中可切换可用连接。
- 每个 Run 固化实际模型连接与模型标识快照，不保存明文密钥。

### 9.2 Tool 类型

- Workflow Tool。
- Model Generation Tool。
- Skill Tool。
- MCP Connector Tool。
- Asset Tool。

Tool 统一声明输入 Schema、输出 Schema、风险等级、审批策略和资产转换规则。

## 10. 权限与审批

采用 Codex 式边界审批：低风险动作自动推进，越过权限边界时暂停。

- 自动执行：读取 Session 资产、查询能力、生成普通文本或媒体、运行允许自动执行的创作任务。
- 需要审批：高成本任务、Agent 发起的外部写操作、Agent 覆盖资产或写入资产库、具有副作用的 MCP Tool。用户在界面中直接点击保存或编辑属于显式操作，不重复弹出 Agent 审批。
- 禁止执行：超出用户权限、读取未授权资产、访问系统密钥、修改系统配置。

审批支持：

- 仅本次允许。
- 当前 Session 允许同类操作。
- 拒绝并返回 Agent 继续规划。

## 11. 后台运行与恢复

- Run 生命周期由服务端拥有，不能依赖浏览器连接。
- 页面关闭或切换路由不取消 Run。
- 客户端通过 AG-UI 重新连接并恢复状态。
- 客户端使用服务端快照和增量事件恢复，不重放浏览器本地推测状态。
- 用户主动点击「停止」才请求取消当前 Run。
- 长时间工作流任务继续由 Pixoma Task Runtime 执行。

## 12. 第一阶段范围

必须交付：

- Studio 菜单与独立三栏 Shell。
- Session 自动保存和完整历史。
- 多模型连接选择。
- Eino ReAct + AG-UI 通信。
- assistant-ui Chat。
- Flow 和 Trace。
- Session Asset、文本编辑与版本。
- 资产库、文件夹和资产详情。
- Workflow、模型生成、Skill、MCP、Asset Tool 框架。
- 审批、中断、恢复、后台运行。

本期不做：

- Session 归档和删除。
- 多人实时协作。
- 完整资产版本 diff 与回滚。
- 对外公开分享。
- 资产交易、计费和配额购买。
- 用户自定义 Agent 编排图。

## 13. 成功标准

- 用户能在一个 Session 中从自然语言目标推进到可复用资产。
- 用户切出页面后，运行继续；返回后恢复完整状态。
- 历史 Session 能完整重建消息、Trace、Flow 和资产关系。
- 工作流、模型生成、Skill 与 MCP 产物统一进入资产体系。
- 任一资产能说明来源、版本、关联 Session 和派生关系。
- 高风险动作在执行前暂停，批准后可恢复原 Run。
- Chat 与 Flow 展示来自同一服务端事实，不出现状态口径差异。

## 14. 验收场景

1. 新建 Session，发送漫画创作需求，标题异步更新，消息不丢失。
2. Agent 生成 Markdown 资产，用户编辑后保存新版本。
3. Agent 使用指定版本和参考图运行工作流，Flow 展示输入输出。
4. 用户切到资产库页面，Run 继续执行；返回后看到完成结果。
5. 用户将分镜图保存到资产库，并在新 Session 中引入固定版本。
6. 直接上传资产进入资产库，详情显示「用户上传」且无关联 Session。
7. 外部写操作触发审批，批准一次后继续；拒绝后 Agent 可重新规划。
8. 模型或 Tool 失败时，历史 Trace 保留错误和恢复动作。
