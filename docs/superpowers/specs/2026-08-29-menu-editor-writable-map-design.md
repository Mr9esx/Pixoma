# 改菜单弹层 · 可写能力地图

## 1. 目标

渠道详情的菜单主视图已是只读能力地图。「改菜单」打开的弹层必须是**同一张图的可写版**：左主键盘、右点下去、底未挂上。人改配置时用的空间，和看配置时用的空间一致。

已确认交互：

- 版面取能力地图（比较稿里的 B），不是大纲树 + 字段表单
- 格子上只改键名；换「这颗键/按钮干什么」只用点下去最顶上一行「动作」
- 主键盘的键和卡片消息上的按钮共用六种动作；按钮可以再打开另一张卡片
- 不留交互债：点一下就能改、一种东西一条改路、未挂上口径与地图相同、列数可改、未保存关窗要问、顶栏只有一个主按钮「保存」

详情页仍然只读。不改菜单/卡片 API、不改六种 `Action` 类型、不改 bot 运行时。

## 2. 范围

**做**

- 重做 `MenuEditorModal` 主视图为可写能力地图
- 打开/保存/关窗（含未保存确认）仍由该弹层负责
- 列数 1–8；加键；动作里新建或选用卡片；未挂上口袋
- 点下去按动作类型编辑内容；卡片消息上改正文、媒体、按钮字
- i18n `zh` / `en`；硬编码中文从编辑器里清掉
- 更新契约测试：弹层不再要求大纲 tab / 卡片库 tab / 手机预览

**不做**

- 不改 `putMenu` / 卡片 CRUD / `Action` 六种类型 / `validateMenuConfig` 的规则含义
- 不把大纲树、卡片库 tab、`PhoneSimulation` 放进弹层
- 不画系统自动的「‹ 返回」
- 不在详情只读地图上改配置
- 不做媒体库；媒体仍是 URL + `kind`（图 / 视频 / 动画）
- 新建卡片不另开一层窗
- 不改架构文档、不改 bot 适配器

本文件覆盖弹层。只读地图仍以 `2026-08-29-channel-menu-capability-map-design.md` 为准，但其中「不改 MenuEditorModal 内部」作废。旧编辑器三栏设计对弹层不再有效。

## 3. 信息架构

与只读地图相同。菜单两层，不是文件夹树。

| 层 | 对方在 Telegram 里遇到什么 | 数据 |
|---|---|---|
| 主键盘 | 输入框上方常驻键，按 `columns`（1–8）分行 | `Menu.items[]`，每项 `{label, action}` |
| 卡片 | 一条消息：媒体 + 正文 + 贴在消息上的按钮 | `Card`；可被多个键或按钮引用；也可未挂上 |

键与卡片按钮共用：

| `action.type` | 人话 | 点下去顶行之下摊开什么 |
|---|---|---|
| `open_card` | 打开「卡片名」 | 那条消息（可写） |
| `open_workflow` | 开始「工作流名」 | Case 名单选 |
| `send_text` | 发这段话 | 那段文本 |
| `send_media` | 发图 | 媒体列表 |
| `open_url` | 打开链接 | URL |
| `copy_text` | 复制这段字 | 那段文本 |

卡片缺失 →「卡片不存在」。工作流 id 找不到 →「工作流不存在」。键/按钮留着，不藏。

未挂上：从主键盘 `items` 出发，沿所有 `open_card`（**含卡片按钮上的**）走到的卡片为已挂；其余进底栏。口袋为空则不渲染。`CardLibraryPane.findReferrer` 只看主键盘的口径废弃，必须与 `orphanCards` 一致。

## 4. 弹层版面

仍是 `Dialog`，接近满屏（可维持现有 `h-[92vh]`）。无投影卡片面；浮层自身允许 shadow。陶土 accent 不用。主 CTA 只有「保存」。

```
┌─────────────────────────────────────────────────────────┐
│ 改菜单    列 [1–8]              未保存?          保存   │
├────────────────────┬────────────────────────────────────┤
│ 主键盘             │ 点下去                              │
│ 格子（键名可写）    │ 动作 [六种 ▾]                       │
│ + 加键             │ （当前路径最后一步的内容，可写）       │
├────────────────────┴────────────────────────────────────┤
│ 未挂上 · N   （虚线块，点了在右栏改这张卡）                │
└─────────────────────────────────────────────────────────┘
```

≥ 920px 左右两栏；&lt; 920px 上下叠：顶栏 → 主键盘 → 点下去 → 未挂上。不横滑。触屏命中 ≥ 44px。

**顶栏**

- 左：标题「改菜单」+ 列数（1–8）。列数只改格子怎么排，不改键的个数
- 中/次要：有草稿时「未保存」，按实际改动计，禁止写死「1 处」
- 右：主按钮「保存」。没有「加菜单项」「新建卡片」并排按钮

**主键盘**

- `grid-template-columns: repeat(columns, minmax(0, 1fr))`
- 每键两行：第一行键名（可写）；第二行人话只读，不可点、不可改
- 选中：边框 `--foreground` + `--muted` 底
- 断引用：destructive 描边，人话 destructive 色
- 末尾虚线空位「+ 加键」。点了追加一颗键（默认 `send_text`、键名为空），并选中它

**点下去**

- 面包屑与只读地图相同：`主键盘 / 键名 / …`；未挂上起点为 `未挂上`。点中间节回退
- **最顶上一行「动作」**：当前路径最后一步若是键或按钮，显示其 `action.type`。这是换类型的唯一入口。最后一步是未挂上卡片时**不显示**动作行——口袋里的卡还没挂在任何键/按钮上，这里只改卡的内容；要挂上，去某颗键或按钮的动作里选这张卡
- 其下按类型摊开可写内容（§5）；未挂上则直接摊开那张卡的消息
- 未选任何键、也未选未挂上：只留栏名「点下去」，不写引导句
- 空键盘：左栏「还没有键」，「+ 加键」仍在

**未挂上**

- 虚线块，文案是卡片名。点了路径从口袋进入，右栏改这张卡
- 摘掉所有 `open_card` 引用后卡片进袋，不自动删除
- 删卡只在正在改这张卡时提供「删除卡片」

## 5. 点选与按钮

路径 state 复用只读地图的 `MapTrailStep`（`item` / `orphan` / `btn`）及 `trailFromItem` / `trailFromOrphan` / `pushTrailButton` / `sliceTrail`。

规则：

1. 点格子 = 选中该键并开始改。没有「先选中再点编辑」
2. 点下去永远在改 **trail 最后一步**
3. 打开卡片时，下面是那条消息。管理用 `name` 用 12px muted 放在消息框上方，可改
4. 卡片上的按钮 = Telegram 消息下方那一排。按钮上改给对方看的字；下方可跟人话一行（只读，与格子第二行相同）
5. 点一颗按钮 = 路径往下走（与只读地图相同）。此时顶上「动作」是**这颗按钮**的类型，可改成打开另一张卡、开始工作流、发文字等
6. 要改回按钮上的字：点面包屑回到那张卡片。同一颗按钮不会出现第二张动作表
7. 在卡片上可删按钮、可「+」加按钮（新按钮默认 `send_text`、字为空）。点进按钮后也可删这颗按钮
8. 选中键后，点下去提供「删除」删这颗键
9. 选中未挂上卡片时不显示「动作」行，只改这张卡；挂上走某颗键/按钮的「打开卡片」

禁止：大纲节点、卡片库卡片、独立 `ButtonEditor` 页、卡片表单里再嵌一套完整 `ActionForm`。

## 6. 六种动作的可写内容

顶上「动作」行之下：

| 类型 | 内容 |
|---|---|
| 打开卡片 | 卡片选择：已有卡片名单选，或「新建」。新建立刻挂在当前键/按钮上，并出现在点下去里，不另开窗。其下是消息：媒体、正文、按钮 |
| 开始工作流 | Case 名单选，显示名称。找不到则「工作流不存在」，仍能重选 |
| 发这段话 / 复制这段字 | 文本，直接改 |
| 发图 | 媒体列表，规则与卡片媒体相同 |
| 打开链接 | URL 原文 |

媒体：每条 URL + `kind`（图 / 视频 / 动画）。有 URL 用 `<img>` 缩略；无 URL 或失败用 muted 色块 + 种类名。不引入图库。

断引用打开卡片：人话与点下去「卡片不存在」，动作行可另选或新建。

## 7. 保存与关窗

- 草稿仍在弹层内（打开时用已保存 `Menu` + `Card[]` 重置）
- 「保存」跑既有 `validateMenuConfig`；失败停在弹层。字段下红字 + 顶栏一行汇总，文案键沿用 `menu.err*`
- 成功：`putMenu` + 卡片增删改（现有顺序可保留），toast，关层，回调刷新只读地图并清空地图路径
- 关层时若草稿相对打开时有改动：先问「丢弃这次修改？」；确定才关并丢草稿。这一问是弹层里唯一额外 Dialog/AlertDialog
- 无改动直接关

## 8. 文案

面向界面的中文走 `menu.*`，中英成对。禁用请 / 您 / 感叹号 / emoji。说明性废话不写。数字 `tabular-nums`。

| 位置 | 中文 |
|---|---|
| 标题 | 改菜单 |
| 主按钮 | 保存 |
| 列数 | 列 |
| 加键 | + 加键 |
| 栏名 | 主键盘 / 点下去 / 动作 |
| 空键盘 | 还没有键 |
| 口袋 | 未挂上 · N |
| 未保存 | 未保存 |
| 关窗确认 | 丢弃这次修改？ |
| 关窗确定 | 丢弃 |
| 人话 | 与只读地图相同 |
| 断 | 卡片不存在 / 工作流不存在 |
| 删除键 | 删除 |
| 删除卡片 | 删除卡片 |
| 加按钮 | + |

不要在界面上写「芯片」。实现里若保留 `chip` class / testid，用户看见的是键、按钮、未挂上卡片名。

## 9. 组件与数据

宿主不变：`MenuCardEditor` 拉数、挂只读 `MenuCapabilityMap`、挂 `MenuEditorModal`。

弹层：

- 版面与 trail 与只读地图同构。优先让只读地图抽出共享壳（键盘 / 点下去 / 未挂上 / trail），只读与可写用模式区分，禁止复制一份 DOM 逻辑
- 顶上「动作」复用现有 `ActionForm` 的类型 Select + 分组（工作流能力 / TG 平台能力），但**不要**在打开卡片的消息里再挂一份完整 `ActionForm`
- 打开卡片时的卡片选择复用 `CardPicker` 行为（已有 / 新建），新建走现有 `buildNewCardDraft`，UI 嵌在点下去里，不挂 `NewCardDialog`
- `OutlinePane` / `CardLibraryPane` / `PhoneSimulation` / `NewCardDialog` 不再被弹层引用；无其它引用则删除，避免第二套入口
- `ItemEditor` / `CardEditor` 内嵌按钮 `ActionForm` 的独立页式编辑废弃，逻辑并入可写点下去

保存链路、`queryKeys.channels.menu` 失效、`onSaved` 刷新地图：保持现状。

## 10. 债清零对照

| 现状 | 目标 |
|---|---|
| 大纲 tab + 卡片库 tab + 表单 | 与详情相同的可写地图 |
| 大纲点一下能改、卡片库要再点「编辑」 | 点格子/按钮/未挂上即可改 |
| 点大纲按钮一张表，点卡片又嵌一套按钮动作 | 按钮字在消息上改，类型在点进去后顶上改 |
| 卡片库只看主键盘引用 | 与 `orphanCards` 相同 |
| 列数无法改 | 顶栏 1–8 |
| 关窗直接丢草稿；「未保存：1 处」写死 | 确认；按实际改动显示 |
| 顶栏加键 + 新建卡片 + 保存 | 主按钮只有保存 |
| 大纲/库/新建窗硬编码中文 | 全部 i18n |

## 11. 测试

保留：`validateMenuConfig`、`menu-flow` 人话/可达/未挂上/trail、只读地图契约、`data-testid='edit-menu'` 打开弹层、`data-testid='menu-editor-modal'`、`data-testid='save-menu'`。

新增/改写弹层契约：

- 点键打开卡片；点卡片按钮推进路径；将该按钮动作改为打开另一张卡后，点下去出现那张卡
- 面包屑回退；未挂上不进主键盘
- 空菜单能加键；断引用键仍在
- 弹层**不得**出现 `tab-outline` / `tab-library` / `phone-simulation`
- 顶栏不得并排 `new-card` 作为第二主入口（新建只在打开卡片动作里）
- 列数控件可把 `menu.columns` 写成 1–8
- 有草稿时关窗出现确认

`ActionForm` 仍是单一 Select + 分组 + `workflow_id` 单数。只读地图 `menu-capability-map.contract.test.ts` 不回退。

## 12. 设计系统

- 语义令牌 + `color-mix`；表面无投影；弹层可 shadow
- 主 CTA 仅「保存」；加键用虚线空位，不是第二颗主按钮
- 920px 重排；聚焦环；hover 后文字不变浅
- 亮暗成对；不用 slate；不用裸 hex
