渠道交互框架 · 整体架构

用户在 TG / 飞书如何看到菜单并交互 · 能力注册表 + 统一交互协议 + 按渠道账户

用户端交互（TG / 飞书）

  • • 主键盘（入口）由管理员显式配置，直达 ≤6
  • • 分组最多一层，只在消息按钮/卡片中出现
  • • 流程全部走消息按钮：选择 → 预览 → 开始 → 确认
  • • 任一步骤可返回上一级或退出（NavContext）
  • • 查看 Case：点「开 Case」→ 选 Case → 预览 → 开始 → 出图

统一交互协议

  • • UI 事件 → CapabilityInvoke → 能力执行 → Result → 渠道渲染
  • • 适配器不感知具体业务，只做翻译与渲染
  • • NavContext 统一处理返回/退出；AccountCtx 按渠道账户
  • • 能力注册表 + JSON Schema 参数校验
  • • 新增业务 = 注册能力，不改适配器

管理端配置

  • • 入口 = 选能力 + JSON Schema 参数表单 + 渠道展示微调
  • • 渠道形态预览：后端 DTO，与真实渲染同源
  • • 菜单 = 能力入口树，持久化 capability_id + params
  • • 用户文案禁用内部术语（inline/callback/extras/capability）
