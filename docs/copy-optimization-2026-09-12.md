## 2. 优化原则（源自 Voice Profile）



1. **术语统一**：工作流（不用 Case）、任务队列（不用 Topic）、计算节点（不用 Edge/instance/agent）、后台（不用管理控制台）、离线 / 在线（不用掉线 / 没通）、停用 / 启用（不用禁用）。

2. **动作起头，去掉礼貌填充**：不用「请 / 麻烦 / 烦请」；按钮用短动词（保存 / 下一步 / 启用 / 停用）。

3. **零装饰**：不用 emoji、感叹号、「注意！」；失败直说「X 失败」，成功直说「已 X」。

4. **页面描述保留引导价值**：页面标题下的 description / 副标题用**用户视角的一句话**讲清「这页是干嘛的、在链路里处在哪」，改写而非删除；不罗列行内操作（启停、凭证、增删改），不用内部名词或自造标签，**不写死具体平台名（后续还会接入更多）**。只有区块内 hint 与标题、字段完全同义时才删除。同一 UI 区域先扫一遍再写，已写过的信息不重复。

5. **不暴露内部实现**：接口字段名（`dispatch_topic`、`subscribe_topics`、`blob root`、`limit`、`offset`、`ack_references`、`bootstrap hash`）、模块名（`Routing`、`agent`、`channel`）不直接当界面文案；错误码只用于机器处理。

6. **与真实行为一致**：按钮名等于实际动作（「完成」→「保存并重启」）；演示内容不承诺真实能力（「打开看看」→「已发送到对话」）。

7. **中英混排规范**：中英文之间加空格（Comfy 运行中）、中文省略号 `…`、产品 / 功能名用「」、命令 / 字段用 `` `code` ``。

8. **状态两档**：健康状态只用「正常 / 存在问题 / 当前不可用」绿黄两档；状态文案「已启用 / 已停用」，动作文案「启用 / 停用」。
